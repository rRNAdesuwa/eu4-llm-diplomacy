# R58：四条款组合议和的执行与保存

统一接口现在能够把归还核心、放弃核心、金币和战争赔款放进同一份和约，并读取每项条款的实际后果。本批在一个游戏进程中完成了英国原生 AI 拒绝、法国明确拒绝、法国明确接受，最后集中保存一次。常用议和条款中，已有实际执行路径的条款增至 **12/19**。

## 这份和约做了什么

本例由法国（FRA）决定是否接受英国（ENG）的让步。四项条款的实际承担国都是英国；归还省份的接收国则是阿马尼亚克（AMG）。法国接受后，原生结果如下。

| 条款 | 实际结算 |
| --- | --- |
| 归还核心 `return_core` | 省份173的所有者、控制者由 ENG 变为 AMG；AMG 的核心保留 |
| 放弃核心 `revoke_core` | 省份175仍由 AMG 持有和控制，ENG 在该省的核心被删除 |
| 金币 `demand_ducats` | ENG 支付1金币；引擎分给 FRA 0.635、AMG 0.073、AUV 0.017、BOU 0.081、FOI 0.067、ORL 0.127，共计1金币 |
| 战争赔款 `war_reparations` | 新增 ENG 向 FRA 支付的赔款关系，起止日期为1455.6.18与1465.6.18 |

接受结束了法英战争，并从原生待处理队列移除了对应提议。两次拒绝均保留战争、173的原所有者和175的 ENG 核心；金币和赔款也没有结算。[完整批次结果](../../work/runtime/diplomacy-query-20261018-r58-core-combined-a/core-execution-batch-001/report.json)包含三次回应及逐条效果。

法国先主动要求相同的四项条款，英国原生 AI 拒绝。后两份英国让步提议由实验脚本明确投递，再交给法国的统一回应接口选择。法国拒绝第一份后，引擎规定英国要到1455.6.18才能再次派遣外交官；脚本正常推进到该日期，再投递第二份，由法国接受。[原生发送条件](../../work/runtime/r58-core-fixture-gates-20261018-001.json)保留了中文日期原因。

## AI 如何查询和执行

先用 `inspect_diplomatic_action("white_peace", "FRA", "ENG", parameters={})` 取得战争列表，再选择实际需要结束的战争。以下 `war_id` 使用该查询返回的值。核心条款用 `core_owner` 明确核心所属国：归还核心时，该国接收省份；放弃核心时，删除该国在指定省份的核心。每种核心条款可在一次请求中选择同一核心国家的1至16个省份。

```python
parameters = {
    "peace_context": {
        "war_id": war_id,
        "direction": "demand",
        "terms": [
            {"action_id": "demand_ducats", "amount": "1.0",
             "payer": "ENG", "claimant": "FRA"},
            {"action_id": "war_reparations",
             "payer": "ENG", "claimant": "FRA"},
            {"action_id": "return_core", "province_ids": [173],
             "core_owner": "AMG"},
            {"action_id": "revoke_core", "province_ids": [175],
             "core_owner": "ENG"},
        ],
    }
}
inspection = api.inspect_diplomatic_action(
    "return_core", "FRA", "ENG", parameters=parameters)
submission = api.execute_diplomatic_action(
    request_id, "return_core", "FRA", "ENG", parameters=parameters)
result = api.get_diplomatic_result(request_id)
```

`request_id` 为本次操作的新编号。第一个动作名选择查询或执行入口，`terms` 描述整份和约；本例通过 `return_core` 入口提交全部四项条款。执行时，引擎重新检查当前候选、参数、完整和约规则和发送条件。查询中的候选、省份、核心国家及原生费用分别返回；本例总费用原始值为26，接受度总值为−100，并取得10项中文接受因素。费用尺度和接受度预测仍按接口返回的核验状态解释，总值不换算成概率。

对于外来提议，`list_diplomatic_actions` 返回 `proposal_id`；AI 用 `peace_offer` 的 `accept` 或 `reject` 阶段回应该编号。结果中的 `effects.return_core`、`effects.revoke_core`、`effects.money` 和 `effects.war_reparations` 记录每项实际后果。`currently_pending=null` 的历史目录行表示当前状态尚未确认；本批用原生回应结果中的 `pending_removed=true` 确认目标提议已经移除。
