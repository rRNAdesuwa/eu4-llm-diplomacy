## 原则：复用游戏规则，单独管理决策来源

桥接负责识别玩家/LLM 请求、校验协议、管理授权和提交动作。属国、政体、宗教、DLC、外交官、冷却、战争、CB 和议和条款等游戏规则，优先调用游戏实际使用的判定方法，由引擎评估当前规则、改革和已加载模组。

授权只决定谁能替受控国作出选择，不使一个本来非法的动作合法。非受控国家仍由原生 AI 决定是否接受；外来提议应可送达受控国，由 LLM 决定回应。接收提议、作出选择和执行双方已达成的结果需要区分。

规则可能分布于 UI 动作选择、脚本条件评估、动作方法、条款方法和命令执行器。必须核对各入口的职责，不能假定存在一个完整通用的 `can_execute` 函数，也不能只调用最终结算函数。

若现有模组锁把来源限制混入动作 `allow`，需识别这一边界并将授权与游戏规则协调处理。不能通过强制整个合法性判定返回 true，或临时清除全局锁，来放行 LLM 动作。

## 每个动作需要恢复的判定阶段

| 阶段 | 输入和输出 | 验收要点 |
|---|---|---|
| 动作选择和显示 | actor、目标及当前上下文 → 实际动作标识、是否存在/可见 | UI 同一位置可以表示不同操作；按钮位置和文字不充当动作标识 |

## 分层职责

1. **版本与原生适配**：管理 hash、RVA、签名、ABI、对象构造/析构和游戏线程要求。按已确认的对象家族整理，未知类型不能套用和平布局。

3. **权限控制**：依据当前阶段的决策国和可信授权决定放行；追踪复制、传输、反序列化和析构中的授权生命周期。未知动作保持现有原生处理，并记录覆盖缺口；不可声称已完整隔离。
4. **动作执行**：检查请求、身份与最新条件，调用正常构造/投递路径，记录实际采用的参数和费用。
5. **结果与实验**：关联请求、响应、状态结果和保存重载；提供可重复基线及失败定位。

外部协议统一，底层按动作使用各自已验证的路径。宣战脚本、和平 action 和外交官命令可以分别适配，不要求物理结构或状态编号一致。

PID、RVA、DLL 路径、请求标记文件和控制台命令由适配层管理。LLM 只选择有明确语义的动作和参数。目录中尚未实现的操作可以显示支持状态，但不得提供一个实际无法执行的成功入口。

每次查询分开返回接口支持、会话就绪、游戏合法性和桥接授权状态。固定模板不支持某个目标，或当前进程没有 DLL，属于接口/运行限制，不等于游戏禁止该外交行为。授权仍在执行时核验，查询本身不授予权限。

### 合法性和接受度返回要求

每项动作查询至少返回：稳定的动作标识、actor/recipient/当前决策国、适用阶段、可见性、合法性、原因、实际参数或候选项、费用及游戏日期/状态标识。对方接受预测为独立结果，不能塞进合法性字段。

判定采用三种状态：`available`、`unavailable`、`unknown`。未找到接口、上下文不完整或读取失败属于 `unknown`，不能伪装成规则禁止，也不能据此允许桥接执行。可用性列表不是对游戏全部动作的穷尽声明。

合法性原因至少包含稳定代码、可读说明和来源，区分原生规则、桥接策略与运行错误。若游戏只返回第一个失败条件，或某一层的诊断尚未导出，需要标记原因列表不完整；不得把一个笼统 bool 扩写成虚构的具体理由。

接受度至少分别标记：是否适用、预测是否可取得、原生评分值及其已确认的单位/尺度、预测响应、明细是否可取得，以及项目列表。每项包含已确认的项目标识、可读名称、原生数值和来源。没有接受方的单方操作返回“不适用”；目标由玩家或 LLM 决策时，不能把原生 AI 评分当作其真实接受预测。未知项目不能根据通常游戏经验自行补上。

游戏评分值通常不是概率。总值可能含阈值、上限、强制条件或其他特殊处理，不能假定等于明细简单相加。总值、明细、尺度和接受预测分别核验，并允许“总值已取得、明细仍未知”。具体原因与接受度都必须绑定同一份提议和游戏状态；议和查询需要完整条约、方向、战争及相关对象，不能只提供双方 tag。

保证独立和支持独立分别使用桥接语义标识。查询识别实际动作后，提交必须明确指定这一动作；目标后来成为属国时，不能把旧的保证请求悄悄改成支持独立。应重新查询并返回状态变化结果。

金额等参数若经引擎裁剪或取整，记录请求值和实际值，并按请求契约处理变化。不能让参数规范化改变请求所指的外交行为。普通查询不能执行动作；查询结果也不授予执行权限。

提供给 LLM 的原因、候选项和接受评分应遵守该国的信息可见范围。内部调试信息另行记录；直接调用引擎不是公开对方秘密信息的理由。

## 每类动作的完成条件

- 已识别各阶段对象、实际动作、actor/recipient 和决策国，核对 ABI、生命周期、来源和所有经过验证的入口。
- 可用/不可用查询与游戏原本判定一致。至少覆盖一个正常情况、一个适用的规则禁止情况，以及一个从查询到执行之间条件变化的情况。
- 合法性原因与原生提示对应；对需要接受的动作，分别验证原生总评分和明细项目的标识、数值、完整性及最终响应。只有总值或部分原因时如实返回，单方操作正确返回“不适用”。
- 普通原生受控国选择实际触发并被拦截；授权选择能执行。记录非受控国外交仍能正常处理，军事经济流程未受新拦截影响。
- 需要双方选择时，验证提议和接受/拒绝分别由正确一方决定；外来提议能供 LLM 查询并选择，过期及撤销有明确结果。
- 正常命令与非法/重复/过期请求有可区分的结果。至少区分已接收、已构造、已投递、已执行、等待响应、已接受/拒绝/失效和实际后果。
- 适用时核对费用、对象状态、持久化和新进程重载；未完成的阶段如实登记。

规则用例按动作选择：属国关系、政体及改革例外、外交官、冷却、DLC、战争/CB、条款互斥等，不能把所有动作强行套入同一条件表。取证优先利用现有日志和只读探针；只有确有必要时才开展新的运行实验。
