# EU4 1.37.5 议和候选生成的副作用边界

`975d40` 的正常 GUI 参数构造不能按“只写临时 offer”处理。本轮已找到引擎全局默认对象的延迟初始化、当前线程 TLS 标志写入和诊断日志路径。脚本条件与战争目标虚函数仍有数据驱动的执行边界，因此目前 **不能开放参数构造自检**。暂停、没有发送 command、构造器正常返回，都不足以证明没有引擎状态副作用。

证据来自磁盘上 SHA256 为 `9ad3efe1af169f40ee577f9dae5debbc87af6fb8b5450fb345ebf110dc4d771a` 的 EXE。新增生成器 `work/trace_peace_candidate_boundaries_1375.py` 输出 `work/reports/native-peace-candidate-boundaries-1375.json`；输入是已经固定的 `native-peace-parameters-1375.json` 和 `native-action-fields-1375.json`。原有 32 个 CFG 逐条校验原始字节后复用，没有重新解码。报告中每项结论有对应指令字节、RVA 和有限覆盖说明，全部 `runtime_verified=false`，没有访问游戏或调用原生函数。

| `97d4e0` | 政府默认对象、确切 `2940/true` 谓词分支、诊断输出 | 实际战争目标类别、`992930` 的剩余辅助调用 |

## 已证实的临时 offer 之外的写入

`97d4e0` 的 `97d83a` 和 `97db60` 的 `97de68` 读取国家 `+1420`。为空时调用 `798dc0`：它先读全局 `233fe88`，若尚未初始化，就分配 `0x438` 字节，调用 `797e30` 构造名称为 `nogovernment` 的对象，安装虚表 `1cb2240`，并在 `798e6b` 发布到 `233fe88`。这里确有引擎全局写入。构造过程还调用 `170d410`、`95110`、`7ab450`；本轮不把这些调用的全部传递效果视为已闭合。

下一层 null fallback 为 `7a73c0`：它读取全局 `242bc80`，必要时分配 `0x8e8` 字节并经 `7a8090` 发布；`7a8090` 还能清理、析构并释放旧全局对象。必须区分可达性：这是指令层面的 null 分支，正常成功的 `798dc0` 返回已构造的非空对象，因此没有证据表明正常候选生成一定会进入这一层。不能把“存在替换路径”改写成“本次调用必然替换”。

可拒绝边界是调用前发现相关国家对象或 fallback 尚未初始化时停止实验，而不是自行调用这些 getter 来“预热”。即使只读看到非空，也还需要对象生存期与并发保护；一次快照不能防止随后替换或析构。

## TLS 依赖并不等于暂停判据

当全局字节 `233fed6` 非零时，`97e1f0` 与 `97e500` 从 `GS:[0x58]` 的数组第 0 项取得 TLS，检查 `+0x0c`；为零时调用 `1a334c0`，随后以该 TLS 的 `+0x10` 决定是否继续相应候选路径。

`1a334c0` 尾跳 `1a33458(reason=2)`。后者通过模块索引变量 `233c574` 找 TLS，并写 `TLS+0x0c=1`。调用者使用字面量索引 0，初始化函数读取索引变量，两者的运行时相等关系尚未实测。准确的静态补充是：两个回调边界 LEA 都等于 `1b690e8`，因此这份 EXE 的初始化循环不会调用任何回调。它也没有在此设置 `+0x10`。

这给出了真实线程依赖，不能据此自行写 TLS，也不能用新工作线程调用后把缺失候选当作业务拒绝。安全实验仍需原生 GUI/游戏线程来源、TLS 状态和不可重入的世界生存期保护。当前切片没有证明“所有函数都只在主线程调用”，也没有找到以暂停状态包围整个构造过程的锁。

## 两处脚本条件入口

`97cda0 → 97c300` 即使把原因输出设为 null，仍会执行省份条件。`97c300` 先通过战争目标 `+78/+70/+58` 得到有效定义；fallback 目标全局是 **`2340030`**，不是附庸定义注册表 `233ffd8`。它建立栈上的国家/省份 scope（虚表 `1c38158`），填入省份 `+20` 与 offer taker。

按 flag 与 taker 是否属于战争 A 侧，条件容器起点为定义 `+140/+378` 或 `+50/+288`。容器 `+8` 是指针，`+14` 是有符号 DWORD count，元素为 8 字节条件指针。`97c5ea` 和 `97c6fa` 调用每个条件的 `virtual+30`。

`97db60` 则从 `233ffd8` 注册表的 `+80` 取附庸定义，调用 `b22380(definition, taker_handle)`。后者以定义 `+48` 指针和 `+54` DWORD count 遍历条件，再调用 `virtual+30`；条件失败即短路，之后清理 scope 可能拥有的临时分配。

这些入口证明调用的是条件求值，不能证明每个具体条件的缓存、嵌套 scope、回调或传递调用都只读。实验前可以只读、严格有界地识别实际条件对象和虚表；空列表只跳过对应的一处循环。不能从一个列表为空推得整个构造器纯净，也不能为了绕过未知条件去修改列表或定义。

## 这轮排除的两个假阳性

`97d8c3` 对通用函数 `35a8f0` 使用 token `2940`、第 5 参 true。两层跳表的准确路由是 `2940-28df=61`，读取 `35beed` 的 byte `6`，再由 `35be68` 的 DWORD 得到 `35ab1e`。这条 true 分支仅调用 `3d79f0/2f1c90`，读取关系和附庸定义；本轮闭合的分支没有非栈写入。`35a8f0` 其他 token 的全局 `233ff08` 初始化不属于这条调用，不能当作此构造器的副作用。

`97e500` 的 `97eaad/97ead1` 看起来会向虚函数返回指针写入。对先前已经识别的 `take_colony` 示例虚表 `1d1fd90`，其 `+f8=d9a020` 明确将 `this+50` 的 16 字节复制到 RDX 并返回 RDX。调用处的 RDX 是栈 wrapper，因此这个具体方法组合中的写入只是更新栈副本。`14cf730` 从类型/ID 注册表解析借用指针，没有对象写入。此结论必须绑定真实虚表/方法字节；其他战争目标与 fallback 对象尚不能沿用。

同一示例的 `+58/+70/+78/+d8/+108` 已分别落到具体叶函数，仅含世界读取或调用者输出写入。政府布尔 variant 的 type 0 也已闭合为 `._N` 类型及 `variant+8` 的单字节读取；错误类型仍存在原生异常路径。

## 日志和最小实验前提

`97d4e0/97db60` 遇到冲突的“成为附庸/臣服附庸”或“成为朝贡国/臣服朝贡国”选项组合，会构造流对象，按条件获取全局日志互斥量 `242b8c8`，输出 `peaceoffer.cpp` 的诊断并 flush。日志是可观察副作用，这把日志锁也不能提供战争、国家和脚本对象的生命周期同步。

下一步应先准备只读的参数前提快照，而不是直接调用构造器：绑定真实战争和双方 full handles、实际参与者与省份数组、有效战争目标/CB/附庸定义、选中的条件向量及其虚表、已初始化政府对象，以及原生线程/TLS。每个向量都应有长度和指针边界；槽位相同或 game 指针未变不能替代世界世代证明。

在实际动态类别和剩余辅助调用闭合之前，`parameter_selftest_ready=false` 保持不变。即便未来只执行“构造、检查、析构”，也必须事先明确允许的全局/TLS/日志副作用、失效与异常后的停止边界，并审查部分构造失败的所有权。此报告没有实现这些运行守卫，没有保存/发送/应用议和，也没有提出用空默认 offer 伪装白和平。
