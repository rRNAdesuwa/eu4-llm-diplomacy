# 外交官可用性与失败原因

统一外交接口会查询行动国的空闲外交官数量，并读取游戏对当前动作的外交官要求。需要外交官而数量为 0 时，查询返回 `unavailable`；执行接口返回 `NATIVE_DIPLOMAT_UNAVAILABLE`，说明“此动作需要空闲外交官，但当前可用外交官数量为0”。

停止改善关系、停止建立间谍网读取的是停止任务的原生要求。实验中两项要求均为 `false`，因此外交官全部忙碌时仍能召回外交官。宣布和移除宿敌使用原生国家命令规则，不附加外交官要求。

## AI 如何读取和处理结果

调用 `inspect_diplomatic_action` 后，读取 `resources.diplomats`：

| 字段 | 含义 |
|---|---|
| `native_requirement` | 游戏是否要求此动作具备空闲外交官 |
| `available_count` | 当前空闲数量；无法读取时为 `null` |
| `availability_verified` | 本次是否成功读取数量 |
| `allocation_verified` | 是否已为动作分配外交官；查询阶段为 `false` |

例如，`native_requirement=true`、`available_count=0` 会在 `legality.reasons` 中增加：

```json
{
  "code": "NATIVE_DIPLOMAT_UNAVAILABLE",
  "text": "此动作需要空闲外交官，但当前可用外交官数量为0。",
  "source": "native_rule",
  "complete": true
}
```

这里的 `complete` 表示已经确定这条失败原因。其他规则的检查范围仍由 `legality.complete` 和各条原因分别说明。外交官数量大于 0 后，接口继续检查关系、冷却、条款、战争背景等原生条件。

AI 应当等待正在归途中的外交官返回，或者先执行适用的停止任务操作，再重新查询。外交官状态无法读取时，接口返回 `NATIVE_DIPLOMAT_CONTEXT_UNAVAILABLE`，保留 `unknown` 或已经确定的其他禁止结果。

`execute_diplomatic_action` 会重新查询，并在游戏帧线程执行前再次检查外交官。即使调用方持有较早的可用查询，实际提交时外交官已经耗尽，原生执行层也会拒绝。普通外交、宣战和议和的拒绝回执都带回具体原因。`get_diplomatic_result` 从请求记录中保留同一结果，调用方使用原请求编号读取即可。

## R68 实际运行

法国原有 1 名空闲外交官。统一执行接口成功派该外交官前往米兰改善关系，数量变为 0。随后批查 19 项常用外交操作及议和上下文；需要外交官的动作明确返回不可用，停止改善关系和停止间谍网仍可用。普通侮辱、宣战、白和平分别在统一执行接口和原生执行复检中返回外交官不足，均未提交业务。

法国在 0 名空闲外交官时成功停止对米兰的改善关系。返回记录给出的到达日期为 1455 年 10 月 17 日；推进至 10 月 18 日后，米兰外交官和原先从勃艮第返回的外交官均已空闲，数量恢复为 2，查询中的外交官不足原因消失。
