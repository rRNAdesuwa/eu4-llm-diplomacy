# 人工实验与日志读取流程

本文档面向希望亲自载入存档、操作游戏、查看日志并判断实验结果的人。不过agent也能在人工操作辅助下很好地完成这一流程。

本文包含两类流程：

1. 使用 `mod\llm_bridge` 导出法国的脚本状态快照；
2. 使用 v9 在同一游戏进程中完成法国宣战、战争分准备和授权议和。

第二类流程可以选择白和平或金币赔款；白和平是当前 v9 同进程验收的默认流程，金币赔款沿用 v7 已验收的原生授权路径。

## 1. 实验前准备

### 1.1 准备存档注意事项

- 仅在 Windows x64、EU4 1.37.4 上测试过。
- 同时只运行一个 `eu4.exe` 进程。
- 如果曾经加载过 DLL，退出游戏并重新启动后再换 DLL。DLL 不能在同一进程中热替换或卸载。

### 1.2 配置项目路径

在项目根目录执行。首次使用时先按[路径配置](路径配置.md)创建 `local.env`，然后在当前 PowerShell 会话中载入配置：

```powershell
$ProjectRoot = (Get-Location).Path
. .\work\native\import-local-env.ps1
Import-ProjectLocalEnv -ProjectRoot $ProjectRoot

$Python = Get-ProjectLocalValue -Name 'EU4_PYTHON'
$Eu4UserData = Get-ProjectLocalValue -Name 'EU4_USER_DATA'
$GameLog = Join-Path $Eu4UserData 'logs\game.log'
$NativeLog = Join-Path $ProjectRoot 'work\native\probe.jsonl'
```

如果当前目录不是项目根目录，先切换到项目根目录，再执行上面的命令。不要把本机绝对路径写入脚本或公开文档。

## 2. 读取模组导出的国家信息

### 2.1 安装或更新脚本模组

我们使用模组导出国家信息。

如果本机还没有安装当前源码对应的模组，在项目根目录执行：

```powershell
& $Python -B .\work\install.py
```

安装器会把仓库中的 `mod\llm_bridge` 复制到 `EU4_USER_DATA\mod\llm_bridge`，并在 `dlc_load.json` 中启用它。完成后重新启动游戏，使游戏重新加载模组。

### 2.2 让法国写出一份快照

1. 1444年剧本，选择葡萄牙。
2. 打开游戏控制台，执行：

   ```text
   run llm_bootstrap.txt
   ```

`llm_bootstrap.txt` 会给法国设置桥接标记和外交锁，令法国原生 AI 的宣战和议和动作被禁止，并留另一条控制路径，并且会立即调用 `llm_bridge_snapshot`。正常情况下，游戏随后会把一组 `EU4LLM|...` 记录写入 `game.log`。启用模组后，月度事件还会继续尝试生成法国快照。

如果只想读取一次法国状态、不想在测试局中设置桥接标记和外交锁，可以先生成一次性的运行文件：

```powershell
& $Python -B .\work\prepare_probe.py
```

然后在游戏控制台执行：

```text
run llm_probe.txt
```

这个运行文件只包含快照效果，不代表模组已经加载，也不会替代模组安装检查。

### 2.3 查看 `game.log`

实时查看最后 100 行：

```powershell
Get-Content -LiteralPath $GameLog -Tail 100 -Wait
```

只筛选本项目的桥接记录：

```powershell
Get-Content -LiteralPath $GameLog -Wait |
    Select-String -Pattern 'EU4LLM'
```

结构化解析完整快照和 ACK：

```powershell
& $Python -m bridge parse $GameLog --pretty
```

需要把解析结果保存为项目内的临时 JSON 文件时：

```powershell
& $Python -m bridge parse $GameLog --pretty |
    Out-File -LiteralPath '.\work\runtime\game-log.json' -Encoding utf8
```

如果日志仍在写入、存在未完成记录，可以暂时使用宽松模式查看诊断结果：

```powershell
& $Python -m bridge parse $GameLog --lenient --pretty
```

宽松模式只适合观察正在写入的日志，不能用于决定是否执行会改变存档的动作。

### 2.4 快照能说明什么

当前 `llm_bridge_snapshot` 导出的是法国 `FRA` 的以下字段：

| 字段 | 含义 |
| --- | --- |
| `treasury` | 国库数值 |
| `manpower_raw` | 人力原始数值 |
| `stability` | 稳定度 |
| `year` | 当前年份 |
| `ai` | 是否为 AI 国家 |
| `war` | 是否处于战争 |
| `locked` | 是否存在 `llm_diplomacy_locked` 标记 |

该快照不包含空闲外交官数量、原生国家句柄、关系冷却或原生和平对象字段。需要这些信息时，应使用下一节的原生只读预检。

### 2.5 让法国向英国宣战

v9 把宣战和授权议和放在同一个游戏进程中完成。固定实验为法国 `FRA` 向英国 `ENG` 使用 `cb_core`、目标省份 `177` 宣战；玩家保持葡萄牙 `POR`。

同样使用 1444 年剧本，先让时间走过一个月。载入测试存档、确认玩家为葡萄牙后，在项目根目录执行：

```powershell
.\work\native\start-automated-diplomacy.ps1 -SavedTestGame
```

这个入口会安装 `eu4_bridge_automated_diplomacy_v9.dll`，并在安装前确认玩家、法国和英国的原生身份。取得当前游戏 PID：

```powershell
$GamePid = (Get-Process -Name eu4).Id
$GamePid
```

运行完整的宣战→白和平实验：

```powershell
& $Python -B .\tools\run_diplomacy_cycle.py `
    --pid $GamePid `
    --test-winwars
```

该命令会依次完成：

1. 写入并消费 `declare-war.request`；
2. 由 v9 调用固定的 `run llm_auto.txt`，让法国向英国宣战；
3. 确认英法战争已经建立；
4. 执行一次实验用的 `winwars`，并自动完成 `tag FRA → tag POR`，恢复玩家；
5. 等待法国外交官和关系冷却满足；
6. 创建并提交白和平请求；
7. 只读确认英法战争关系已经清空。

外交官和外交操作有冷却时间，需要由玩家推进日期。日志中的关键事件是：

```text
automatic_diplomacy_installed
automatic_war_begin
automatic_console_result
automatic_war_runtime_confirmed
authorization_selftest_passed
test_winwars_fixture_applied
whitepeace_submitted
llm_authorized_peace_execute_entry ... state_raw=2 ... authorization=2
```

游戏日志中应看到：

```text
EU4LLM|ACK|war_auto_01|applied
EU4LLM|FIELD|live|ai|1
EU4LLM|FIELD|live|war|1
EU4LLM|FIELD|live|locked|1
```

完整结果保存在 `work\runtime\v9-cycle-validation.json` 和 `work\runtime\automatic-cycle-settlement.json`。其中 `both_pair_at_peace=true` 且 `player_slot=189` 表示英法已经结束战争、玩家已经恢复为葡萄牙。

如果只想让法国宣战，不继续白和平，可以只创建宣战请求：

```powershell
& $Python -B .\tools\request_diplomacy.py declare_war --pid $GamePid
```

旧的 `prepare_war_test.py` 仍可用于脚本层单测；v9 的人工实验不需要再手动清除外交锁或运行 `llm_war_test.txt`。

## 3. 复现原生金币赔款实验

### 3.1 实验目标和成功标准

目标是让玩家控制葡萄牙 `POR`，由法国 `FRA` 向英国 `ENG` 提出一档原生金币赔款。

实验分为三个证据层次：

1. **前置条件通过**：玩家是 `POR`，法国和英国身份有效，法国有可用外交官，关系冷却已满足。
2. **原生请求执行**：`probe.jsonl` 出现法国向英国开始构造、提交并进入原生执行器的记录。
3. **实际结算完成**：战争结束、停战和国库变化在游戏内出现，并通过实验前后存档比较确认。

只有第一层不能证明请求已经发送；只有第二层也不能单独证明金币已经结算。需要第三层时，必须保存实验后的存档并进行存档比较。

### 3.2 准备游戏状态

在游戏内手动完成以下操作：

1. 载入测试存档并暂停，确认玩家为葡萄牙。
2. 按[v9 宣战与议和流程](#25-让法国向英国宣战)让法国进入战争状态。
3. 如果需要金币赔款，在 v9 的宣战确认和授权自检通过后运行：

   ```powershell
   & $Python -B .\tools\request_diplomacy.py gold --pid $GamePid
   ```

   `run_diplomacy_cycle.py` 的最终动作是白和平；金币实验用这个请求替代最后一步。

4. 确认游戏界面显示玩家仍为葡萄牙。


### 3.3 启动授权实验模式

如果需要更换游戏进程或确保没有旧 DLL，先执行：

```powershell
.\work\native\restart-game.ps1 -SavedTestGame
```

重启后由人类确认测试存档已经正确载入、玩家仍为 `POR`。游戏运行并载入目标存档后，在项目根目录执行：

```powershell
.\work\native\start-automated-diplomacy.ps1 -SavedTestGame
```

该脚本会进行以下检查：

- 只存在一个目标 EU4 进程；
- 游戏可执行文件与已验收版本一致；
- 当前玩家是 `POR`；
- `FRA` 和 `ENG` 的原生身份有效；
- v9 授权版 DLL 的哈希正确；
- DLL 已成功加载。

该步骤不会自动发出宣战或和平请求。加载完成后，返回游戏窗口，让游戏帧继续运行；宣战和议和随后都在这个进程中完成。

### 3.4 检查授权自检

先查看 v9 是否安装并通过授权自检：

```powershell
Select-String -Path $NativeLog `
    -Pattern 'authorization_selftest_passed|authorization_selftest_failed'
```

先看到 `automated_diplomacy_installed`、`automatic_war_runtime_confirmed` 和 `authorization_selftest_passed`，再创建白和平或金币请求。

### 3.5 创建一次金币赔款请求

确认只有一个游戏进程后取得 PID：

```powershell
$GamePid = (Get-Process -Name eu4).Id
$GamePid
```

执行一次请求：

```powershell
& $Python -B .\tools\request_diplomacy.py gold --pid $GamePid
```

`request_diplomacy.py` 会检查玩家国家、法国外交官、日期门槛、关系冷却和授权自检，并创建 `work\native\gold-peace.request`。v9 随后在游戏线程中重新检查这些条件并执行请求。

### 3.6 读取原生实验日志

查看本次请求相关事件：

```powershell
Select-String -Path $NativeLog `
    -Pattern 'gold_peace_begin|native_gold_terms|gold_peace_submitted|authorized_native_validity_result|authorized_received_offer_fields'
```

重点事件的含义如下：

| 事件 | 解释 |
| --- | --- |
| `automatic_war_runtime_confirmed` | 法国与英国已经进入战争 |
| `authorization_selftest_passed` | v9 的和平授权和运行环境检查通过 |
| `gold_peace_begin` | 原生金币和平请求开始处理；应看到 `actor=FRA`、`recipient=ENG` |
| `native_gold_terms` | 原生金额、费用和有效性检查结果；重点看 `valid` 和 `send` |
| `gold_peace_submitted` | 请求已提交给原生处理路径，不等于已经完成结算 |
| `authorized_native_validity_result` | 原生有效性检查结果；需要结合状态变化读取 |
| `authorized_received_offer_fields` | 接收端收到的和平对象字段和参与方信息 |
| `native_peace_authority_blocked` | 未授权和平动作被权限锁拦截 |

本次已验收的金币基线中，原生金额记录为 `currency_delta_raw=34400`，对应游戏显示的 34.400 金币。其他游戏状态或条款下的金额不能仅凭这个数值推断。

### 3.7 保存并核对实际结算

如果需要证明金币确实结算：

1. 在请求前保存实验前存档，例如 `gold-before.eu4`。
2. 确认游戏内战争结束、停战关系和国库变化。
3. 另存为不同名称，例如 `gold-after.eu4`。
4. 使用只读存档检查器：

   ```powershell
   $BeforeSave = Join-Path $Eu4UserData 'save games\gold-before.eu4'
   $AfterSave = Join-Path $Eu4UserData 'save games\gold-after.eu4'
   $Evidence = Join-Path $ProjectRoot 'work\runtime\gold-settlement.json'

   & $Python -B .\work\inspect_gold_settlement.py `
       --before $BeforeSave `
       --after $AfterSave `
       --output $Evidence
   ```

检查输出中的：

- `settlement_verified`；
- `treasury_deltas`；
- `eng_fra_active_wars`；
- `province_owner_changes`；
- 实验前后日期是否一致。

国库差异还要与 `native_gold_terms` 和和平对象日志一起解释；单独观察国库变化不能排除日期推进、其他收入或其他条款的影响。

## 4. 日志和请求文件的位置

| 文件 | 用途 | 证据级别 |
| --- | --- | --- |
| `EU4_USER_DATA\logs\game.log` | 模组脚本快照、脚本 ACK 和游戏普通日志 | 脚本层证据 |
| `EU4_USER_DATA\logs\error.log` | 游戏脚本或资源加载错误 | 错误诊断 |
| `EU4_USER_DATA\logs\setup_error.log` | 启动和设置阶段错误 | 启动诊断 |
| `work\native\probe.jsonl` | v9 的宣战、授权和和平请求事件 | 原生过程证据 |
| `work\native\declare-war.request` | v9 宣战请求标记 | 请求输入 |
| `work\native\test-winwars.request` | 实验战争分请求标记 | 实验输入 |
| `work\native\whitepeace.request`、`gold-peace.request` | 和平请求标记 | 请求输入 |
| `work\runtime\*.json`、`*.jsonl` | 人工保存的实验快照和分析报告 | 归档证据 |

`probe.jsonl` 会在 DLL 启动时重新创建。重要实验结束后应立即复制并改成唯一名称，例如：

```powershell
Copy-Item .\work\native\probe.jsonl `
    .\work\runtime\probe-gold-20261005.jsonl
```

不要把存档、完整日志、minidump 或 `work\runtime` 中的个人实验数据提交到公开仓库。

## 5. 常见问题和停止条件

### `game.log` 没有 `EU4LLM` 记录

依次检查：

1. 游戏是否重新启动过并加载了启用的模组；
2. 控制台是否真的执行了 `run llm_bootstrap.txt`；
3. 当前是否仍为法国 AI；
4. `EU4_USER_DATA` 是否指向当前游戏实际使用的用户数据目录；
5. 是否查看了正确的 `game.log`。

### 授权自检没有通过

先确认游戏窗口处于前台、游戏帧正在运行、玩家是 `POR`，并查看 `probe.jsonl` 是否出现 `automated_diplomacy_installed` 和 `automatic_war_runtime_confirmed`。满足条件后重新运行 `tools/request_diplomacy.py` 或完整的 `tools/run_diplomacy_cycle.py`；如果 DLL 不是当前 v9 版本，重启游戏后重新安装。

### 没有空闲外交官或关系冷却未通过

回到游戏中推进日期，等法国外交官和关系冷却满足后，再运行 `tools/request_diplomacy.py` 或完整的 `tools/run_diplomacy_cycle.py`。

### DLL 加载失败或提示已经加载

退出游戏并重新启动。不要在同一进程中热替换、重复注入或尝试卸载 DLL。`run llm_stop.txt` 只能清理模组标记，不能卸载 DLL。

### 只有请求文件，没有原生事件

请求文件存在只说明请求已排队。检查游戏窗口是否在运行、`probe.jsonl` 是否仍在增长，以及是否出现 `authorization_selftest_passed`。不要重复创建同名请求或同时排队多个请求。

## 6. 实验结束

1. 保存实验结果和必要的日志副本。
2. 如果启用了脚本模组锁，在测试局控制台执行：

   ```text
   run llm_stop.txt
   ```

3. 退出游戏，使 DLL 随进程结束。
4. 检查 `git status`，确认没有把 `local.env`、存档、日志或 `work\runtime` 数据加入提交。
5. 在实验记录中写明：游戏版本、存档名称、控制台操作、DLL 模式、请求文件、关键日志事件和最终存档比较结果。
