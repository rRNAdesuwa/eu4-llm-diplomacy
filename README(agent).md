# EU4 单机外交桥接原型

当前状态入口：[HANDOFF.md](HANDOFF.md)（2026-10-05）。新对话或协作者先读交接文档，再按索引核对证据；以下安装部分是模组层说明，不代表完整原生外交能力。

当前联盟需求的系统逆向入口：[联盟外交逆向梳理](docs/联盟外交逆向梳理.md)、[逆向索引模块](reverse_engineering/README.md)。先复用已绑定 EXE 哈希的函数/来源，再按优先问题深入；静态结论与归档运行身份分别维护。

目标：玩家与外部 LLM 交流，法国保持原生 AI 国家，LLM 接管外交决策，原生 AI 保留军事经济。当前仍是单机原型，没有配置真实 LLM 服务。不使用电脑/UI 自动化；助手已负责自动重启和 DLL 安装，用户手动载入、控制台和推进。

已实测：v9 在同一游戏进程中让法国向英国固定宣战，执行实验战争分，然后提交授权白和平并结束英法战争；玩家恢复为葡萄牙。v7 金币赔款的原生 AI 接受、结算、保存和重载也已单独验收。自然战争分接受、v9 保存重载和原生割地仍未验收。

当前运行入口为 v9：`eu4_bridge_automated_diplomacy_v9.dll`，使用 `tools/run_diplomacy_cycle.py` 串联固定宣战、授权白和平和日志验收；`tools/request_diplomacy.py` 可单独创建宣战或金币请求。完整外交覆盖和真实模型服务仍未接入。

## 安装

先按[路径配置](docs/路径配置.md)复制 `local.env.example` 为 `local.env`，填写本机的 `EU4_GAME_ROOT`、`EU4_USER_DATA` 和 `EU4_PYTHON`；真实路径只保存在被忽略的 `local.env` 中。随后运行 `python work/install.py`，从本机 1.37.4 原版脚本构建独立覆盖模组，复制到用户数据目录的 `mod/llm_bridge`，并在 `dlc_load.json` 末尾启用。第一次运行会备份原 `dlc_load.json` 到 `work/backup/`。不更改游戏安装目录。需要重新启动游戏加载。

安装器从 `local.env` 读取路径，换机器只需重新填写本地配置。模组复制完整外交动作和 on_actions 原版文件，因此可能与改动同文件的其他内容模组冲突；当前保留已启用的汉化模组。

## 当前控制边界

- v9 当前提供固定 FRA→ENG 宣战、实验战争分和授权白和平/金币请求；模组脚本锁仍主要覆盖法国普通 `declarewar` 和 `break_alliance`，不代表完整外交接管。
- 关系修正是测试用脚本效果，不是普通外交官改善关系操作；不能声称实现了正常费用和耗时。
- 没有外国情报导出，避免未验证的信息可见性造成作弊。
- 模型无法输入任意脚本，命令编译器限制动作、国家和请求编号。
- 月度事件是否按预期触发、数值日志格式和外交锁均以实测记录为准。

## 停止与回滚

测试局控制台可运行 `run llm_stop.txt` 清除法国导出与外交锁标记。移除启用列表中的 mod/llm_bridge.mod 并重启游戏，可停止加载模组；若期间未调整其他模组，可恢复 work/backup/dlc_load.json。保留模组文件不会影响未启用的游戏。

不要在正常存档中开启实验性锁：这会改变 AI 的行为；停用模组不会自动清除存档内的桥接标记。先执行停止命令，或回到未使用桥接的存档。
