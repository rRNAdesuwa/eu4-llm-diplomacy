# R53：取消条约的原生候选与实际后果

`annul_treaties` 已接入统一目录、查询、执行和结果读取。实际完成英国原生AI拒绝法国要求，以及法国对同一份外来提议分别拒绝、接受；三个结果都已保存并在新进程核对。法国接受后解除与热那亚、教宗国的同盟，并留下两条取消条约记录。

取消条约条款使用 `country` 指定被要求取消条约的国家，使用 `treaty_partners` 指定条约伙伴。同一条款可以选择多个伙伴；桥接从游戏生成的候选中选择，并让游戏检查完整和约。

本阶段已在独立战争存档完成九项原生查询。观察玩家为葡萄牙（POR），接口控制法国（FRA），英法正在交战。

| 查询方向 | 被要求取消条约的国家 | 游戏实际生成的伙伴候选 |
| --- | --- | --- |
| 法国向英国要求取消条约 | ENG | GEL、SCO、SWE、ULS、UTR |
| 法国向英国提供取消条约 | FRA | GEN、PAP、PRO、SAV、SCO、ULS |

空条款查询返回候选；选择具体伙伴后，接口才能检查这份完整和约。原生单伙伴和双伙伴查询均通过完整条款检查，序列化副本中的国家、伙伴及已选状态与源对象一致。英国方向取得9项接受因素，法国让步方向取得8项；本场景评价均为−100。原生聚合字段在单伙伴时为10、双伙伴时为20，与1.0金币组合时为11；这些数值与接受评价分别记录。

金币和取消条约可以同时选入和约。承认战败与取消条约组合时，原生规则返回“要求承认战败时，不能附带其他任何条件”。指定错误国家FRA、要求其取消与GEL的条约时，原生候选没有匹配项。[九项原生查询报告](../../work/runtime/diplomacy-query-20261018-r53-peace-a2-annul/native-annul-query-001/report.json)保存了完整参数、候选和规则结果。

公开接口的九项查询也已取得真实事件。初次结果发现，多伙伴条款在游戏中对应两条原生条款，公共层却按一个对象计数，因而误报规则不完整。公共层现已按伙伴数计算，并用原来的九个事件重新投影；各项合法性、实际参数和完整性均匹配原生结果。[离线修正报告](../../work/runtime/diplomacy-query-20261018-r53-peace-a2-annul/annul-public-reprojection-002/report.json)保留原失败报告的哈希，没有重新查询或执行业务。

法国已向英国要求取消与瑞典（SWE）、乌得勒支（UTR）的条约。英国原生AI拒绝，双方继续交战，两组同盟保留，也没有新增相应的取消条约记录。[主动执行报告](../../work/runtime/diplomacy-query-20261018-r53-peace-a2-annul/outbound-annul-001/report.json)的17项检查通过；请求发布、消费和业务提交各一次。结果另存为 `llm_diplomacy_peace_annul_outbound_rejected_20261018_r53a.eu4`，在新进程重新载入后，[重载检查](../../work/runtime/diplomacy-query-20261018-r53-peace-b-outbound-reload/outbound-reload-001/report.json)通过。

接受实验使用法国与热那亚（GEN）、教宗国（PAP）的关系。这些联盟已在准备存档的[流式关系清单](../../work/runtime/peace-annul-treaties-native-20261018-r53-001/baseline-treaties.md)中确认；游戏候选也包含相同伙伴。

英国要求法国取消与GEN、PAP条约的实验提议已进入法国队列，推进一天后仍等待法国选择，原生日志记录了跳过法国自动回应。待处理提议保存为 `llm_diplomacy_peace_annul_inbound_pending_20261018_r53c.eu4`。这是操作员指定时点发送的一次原生实验提议，英国的自主发起策略不属于这次实验。

法国从该存档恢复提议后，已通过公开接口明确拒绝。[拒绝报告](../../work/runtime/diplomacy-query-20261018-r53-peace-d-inbound-reject/inbound-reject-002/report.json)的22项检查通过，提议被移除，战争继续，两组同盟保持存在。D001首次查询发现公共层漏接取消条约入站参数，执行次数为0；补齐参数与后果解析后，D002才首次提交拒绝。

另一新进程载入相同待处理存档，由法国明确接受。[接受报告](../../work/runtime/diplomacy-query-20261018-r53-peace-e-inbound-accept/inbound-accept-001/report.json)的22项检查通过：战争结束、提议移除，FRA–GEN和FRA–PAP的同盟均从存在变为不存在，两条取消条约记录从不存在变为存在。开始日期均为1455.5.18，原始值56549088；终期字段为游戏的43808760哨兵，存档未写固定结束日期。

拒绝结果保存为 `llm_diplomacy_peace_annul_inbound_rejected_20261018_r53d.eu4`，接受结果保存为 `llm_diplomacy_peace_annul_inbound_accepted_20261018_r53e.eu4`。[拒绝重载](../../work/runtime/diplomacy-query-20261018-r53-peace-f-rejected-reload/inbound-reload-001/report.json)和[接受重载](../../work/runtime/diplomacy-query-20261018-r53-peace-g-accepted-reload/inbound-reload-001/report.json)各9项检查通过，分别核对原生关系、公开后果和流式存档。接受存档按 `first=FRA`、`second=GEN/PAP`、`start_date=1455.5.18` 保留两条记录；重载后同盟仍已解除。

AI查询时先选择当前战争编号，再提交完整参数。例如，法国向英国索取取消条约：

```python
parameters = {"peace_context": {
    "war_id": war_id,
    "direction": "demand",
    "terms": [{"action_id": "annul_treaties", "country": "ENG",
               "treaty_partners": ["SWE", "UTR"]}]
}}
inspection = api.inspect_diplomatic_action(
    "annul_treaties", "FRA", "ENG", parameters=parameters)
submission = api.execute_diplomatic_action(
    "my_unique_request", "annul_treaties", "FRA", "ENG", parameters=parameters)
result = api.get_diplomatic_result("my_unique_request")
```

`country` 是被要求取消条约的国家，伙伴列表须明确填写。空 `terms` 用于发现候选；实际提交须带选定条款。查询分别返回游戏合法性、桥接授权、候选和接受因素，执行前会再次检查当前原生状态。
