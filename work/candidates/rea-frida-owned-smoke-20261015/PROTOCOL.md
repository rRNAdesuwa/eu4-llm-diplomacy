# Owned-fixture Frida smoke: prepared source, not executed

This candidate tests whether the existing Windows Frida 17.23.2 binding can attach to a controller-created Python waiting child, load one small script, capture its one send, unload and detach. No fixture, REA, Frida or Node test has been started while preparing this source. The candidate is unsealed and requires root's source review before the explicit run-reviewed operation. It does not establish any EU4 entry, stack, native readiness, lease, or diplomatic effect.

## Fixed launch and ownership

The public launcher accepts only check or run-reviewed. It has no PID, device, endpoint, executable, script, duration, native address or game argument. check only hashes files. The selected Python and Node executables and REA dispatcher are fixed in protocol.py, with selected external hashes in source-manifest.json. No Codex configuration or environment values are read or logged by this candidate. Normal child environment inheritance remains necessary; it is not a logged or fully pinned reproducible input.

run-reviewed creates one fresh random 128-bit nonce directory under work/reports/rea-frida-owned-smoke-20261015 and an exclusive claim. It loads the exact reviewed job_tree r3 bytes (SHA256 5fca5b41161829a15554b08371e3fc64765164479e41bda015fec910972e9011). That helper starts the controller suspended, assigns its exact new Popen handle to its unnamed Job, then resumes it. The fixture and REA CLI are spawned without breakaway and inherit that same Job; there is no nested helper Job. The launcher itself is outside the Job. Controller source checks inherited membership and the required limits; it does not claim that checking anonymous limits independently authenticates the Job identity. Identity comes from the reviewed launch path.

Limits are process/job commit 768 MiB, concurrent members 8, cumulative over 8 refusal, KILL_ON_JOB_CLOSE, and the reviewed 45-second polling deadline. This is not a hard whole-function interrupt: setup, bounded waits and cleanup can extend it. The controller's CLI wait is separately capped at 25 seconds after Popen; 1500 ms is REA's post-load message wait, not a total attach/load/detach deadline. Each CLI log has a 64 KiB acceptance bound during polling and after exit; a writer can overshoot before refusal. The outer helper's controller stdout/stderr acceptance bound is 2 MiB per stream.

The controller creates its own fixture with a private stdin pipe and verifies its ready record. GetProcessTimes uses only that exact Popen handle to obtain and recheck the creation FILETIME. There is no OpenProcess, target enumeration, process lookup, external PID parameter or game reader. REA argv attach PID is derived only from this new child. The script receives only schema, that PID and the fresh nonce. It inspects Frida Process.id/platform/arch/pointerSize and sends one ASCII object below 256 bytes. It has no Interceptor, NativeFunction, target memory/data read, field write, filesystem/network access or timer. Frida attachment and agent injection can allocate or change target runtime memory; this is not pure RPM, and no total memory-written-false claim is made.

## Evidence acceptance

The fixed command is Node, REA scripts/rea.mjs, instrument-with-frida attach OWN_CHILD_PID --duration-ms 1500 --script-file ABSOLUTE_RENDERED --device-id local --format json --full-output. No filtered/token-limited/partial output is accepted. The rendered source contains the JSON config prefix and complete smoke.js; its full SHA256 is pinned before and after CLI, and must equal normalized_result.source_sha256. The raw CLI stdout JSON and stderr are retained without parsing away fields. Stderr must be empty for acceptance.

evidence.py implements the independently audited REA field-contract, specialized to this owned Python payload. It requires strict UTF-8 ASCII-profile JSON, one document, bounded depth/nodes/bytes, exact keys, no duplicate keys at any level, floats, NaN/Infinity or trailing records. Evidence operation is instrument_with_frida; provider is frida/Frida/version null, authority external-service, predicate rea.frida.instrumentation-observation. This null provider version does not authenticate binding 17.23.2; the separate package/binding/source pins do. Parameters and normalized result must agree on local/attach/session/PID; target must display python.exe and the own PID. UUIDs, source kind/path/hash, one script identity, exact selected limitations and semantic EvidenceID projection are checked.

There must be exactly one message, exactly script_id/type/payload, type send and the own script ID. Payload is exactly the six small schema/PID/platform/arch/pointer_size/nonce fields. Error/log/extra messages, description/stack, binary keys even empty, truncation/redaction keys even false, messages_truncated true, bad source/nonce or either non-null cleanup_error fail closed. CLI ok/exit0 alone cannot prove script success. State running is the pre-cleanup snapshot and must not be replaced with a guessed detached state. REA's provider cleanup report is separate from own-child lifecycle evidence.

## Cleanup and result

The controller finally closes only its private fixture pipe, sends the nonce stop line when live, waits for that exact child, and if necessary terminates only its own Popen handle. The REA CLI is likewise collected through its own Popen handle. A forced fixture termination, timeout, missing handle receipt, nonzero exit or any failure remains unknown. The outer reviewed Job helper independently waits for zero active members; a timeout/remaining descendant uses only its own Job. The launcher accepts only a clean zero-member Job receipt, a clean controller receipt, fixture exit0 with graceful stop and handle close, exact raw Evidence replay, and pre/post selected source pins. No failure automatically retries or reattaches. No process other than the newly created controller tree can be assigned, killed or selected by this candidate's target path.

The final successful label is owned_fixture_attach_scriptload_observed. It is not installed EU4 provenance, engine availability for every target, arbitrary Frida compatibility, EU4 cleanup/entry authentication or permission to run an EU4 script. native_ready and lease stay false; native game calls and game access stay zero. Source pre/post hashing is bounded change detection, not a file locking or hostile-writer TOCTOU guarantee. Selected external pins do not claim a complete transitive Node/Python DLL dependency closure.

## R2 corrections and limited offline verification

The exact 11-file R1 preimage (nine sources, manifest and source preparation receipt) is retained under prepared-r1-preimage with prepared-r1-preimage-manifest.json. R1's controller receipt used floating seconds, which its launcher ASCII/integer JSON profile rejects. R2 records integer elapsed_ms; new test_profile_r2.py calls the actual run_cli with a collected Popen fake and verifies that its serialized nested controller receipt is accepted by the launcher's byte decoder. It also demonstrates rejection when a floating seconds field is restored.

Source package JSON now uses strict_json with ascii_strings=False; default Evidence parsing stays ASCII. UTF-8 decoding, duplicate-key refusal, nonfinite/safe-integer/type limits and byte/node/depth limits remain. Unpaired surrogate strings fail. On the fixed installed package.json SHA7efb59d2, file-only inspection found no non-ASCII decoded strings; no author information was printed. This is a source-profile capability correction rather than a reproduced failure for that pin. Synthetic Unicode package strings exercise the positive and negative boundary.

CLI meta.duration now requires the observed Math.round result plus ms shape: zero or a nonzero ASCII decimal integer (at most 16 digits), then ms. This is a format guard, not a total attach deadline. New positive and malformed cases use full independently built wire envelopes with a correct semantic ID. The old test_contract.py fixture's duration was corrected to 1500ms, but that existing suite is not rerun. verify_offline_r2.py launches only test_profile_r2.py through the exact reviewed Job r3; there is no Node, fixture, REA or Frida invocation. Its file-only --check replays source/output pins without rerunning tests. Root still must independently review the corrected source before any run-reviewed smoke operation.
