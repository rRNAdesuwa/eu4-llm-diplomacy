# 赠送礼物与影响国家接口

`send_gift`（赠送礼物）和 `influence_nation`（影响国家）都是单方外交动作。它们由行动国 FRA 发起，阶段为 `initiate`；目标国不需要接受，动作也不会产生入站提议。桥接会在提交前再次读取游戏当前状态，只有原生合法性通过时才向游戏投递请求。

## 四个统一入口

四个入口分别负责发现动作、查询当前原生条件、提交一次明确请求和读取实际结果：

```python
target = "PAP"

# 1. 从动作目录确认动作及参数定义
catalog = tools.list_diplomatic_actions(actor="FRA", recipient=target)

# 2. 查询赠送25金币的原生规则、费用和当前合法性
inspection = tools.inspect_diplomatic_action(
    "send_gift", "FRA", target,
    phase="initiate", parameters={"ducats": 25})

# 3. 仅在查询为 available 时提交；每次业务使用新的请求编号
if inspection["legality"]["status"] == "available":
    submission = tools.execute_diplomatic_action(
        "gift_FRA_PAP_001", "send_gift", "FRA", target,
        phase="initiate", parameters={"ducats": 25})

# 4. 读取原生执行结果；重复读取不会再次提交
result = tools.get_diplomatic_result("gift_FRA_PAP_001")
```

影响国家使用同一组入口。它没有调用者可填写的金额、意见或持续时间：

```python
target = "SAV"
inspection = tools.inspect_diplomatic_action(
    "influence_nation", "FRA", target,
    phase="initiate", parameters={})

if inspection["legality"]["status"] == "available":
    submission = tools.execute_diplomatic_action(
        "influence_FRA_SAV_001", "influence_nation", "FRA", target,
        phase="initiate", parameters={})

result = tools.get_diplomatic_result("influence_FRA_SAV_001")
```

### 动作、参数和费用

| 动作 | `action_id` | `phase` | `parameters` | 费用和原生数值 |
| --- | --- | --- | --- | --- |
| 赠送礼物 | `send_gift` | `initiate` | 必须是 `{"ducats": 整数}`；金额至少25，且为25的倍数，最大2,147,475 | 行动国国库支付请求金额；金币原始值按 `1000` 缩放 |
| 影响国家 | `influence_nation` | `initiate` | 不传参数或传 `{}`；不能指定金额、意见或持续时间 | 原生对象选择费用、意见和持续时间；费用以国库金币计，原始值按 `1000` 缩放 |

赠送礼物的查询会在 `costs.items` 中列出 `resource="treasury"`、`country="FRA"`、`source="request"`、`amount` 和 `amount_raw`。影响国家的 `costs.items` 使用 `source="native_rule"`，同一费用还会保留在 `influence.native.cost_raw`；调用者应使用这个原生费用，不要根据意见或持续时间自行推算。

两项查询都把 `interface_support`、`authorization` 和 `legality` 分开返回。`interface_support.execute` 表示已安装提交适配，`authorization.status` 表示当前受控行动国可以使用该适配，`legality.status` 才是这一次目标和当前游戏状态是否允许执行。赠送礼物的公共查询只展示受控行动国的 `gift.controlled_treasury`；目标国国库的原生证据不作为公共字段提供。

### 接受度不适用

这是单方动作，查询中的接受度固定表达为不适用，而不是把它当成目标国接受或拒绝：

```json
{
  "acceptance": {
    "applicability": "not_applicable",
    "prediction_available": false,
    "predicted_response": "not_applicable",
    "native_total": null,
    "items": [],
    "complete": true
  }
}
```

因此，执行成功看 `submitted=true` 和 `game_outcome="executed"`，不看 `acceptance` 的接受结果。请求合法性在提交时再次检查；查询可用并不替代执行时检查。

## 查询结果字段

公共检查结果保留动作身份和会话绑定字段：`action_id`、`actor`、`recipient`、`phase`、`parameters`、`interface_support`、`authorization`、`legality`、`costs` 和 `acceptance`。其中：

- 赠送礼物的 `gift.amount` 有 `ducats`、`raw`、`value`、`unit="ducats"`、`scale=1000`、`payer` 和 `receiver`；`gift.controlled_treasury` 有受控国、原始国库值、单位和尺度。
- 影响国家的 `influence.cost` 来自原生规则；`influence.opinion` 使用 `unit="opinion"`、`scale=1`，`influence.duration` 使用 `unit="months"`、`scale=1`。查询示例中原生意见为25、持续120个月。
- `legality.reasons` 保留游戏原生说明。`status="unavailable"` 时，执行入口不会提交到游戏，`submitted` 为 `false`。

实际结果通过 `get_diplomatic_result` 返回统一外层字段 `request_id`、`action_id`、`status`、`submitted`、`game_outcome` 和 `result`。`result` 中的动作对象还会给出 `complete`、`verified`、`native_state` 和 `native_outcome`；`execution_verified` 与 `request_binding_verified` 用于确认效果和请求身份均已由原生事件核对。
