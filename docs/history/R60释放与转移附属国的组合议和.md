# R60：释放与转移附属国的组合议和

统一外交接口现在可以把释放附属国、转移附属国、金钱和战争赔款放入同一份和约，查询整份和约的原生规则，再提交并读取实际结果。本批在一个游戏进程中完成英国原生 AI 拒绝、法国明确拒绝、法国明确接受三种回应，最后集中保存一次。常用议和条款已有实际执行证据的数量从12项增至14项，总范围仍为19项。

## 这份和约具体做了什么

英国原先拥有两个附庸：TYR、LEI。法国要求英国释放 TYR，把 LEI 转为法国附庸，支付1金币，并向法国支付十年战争赔款。

| 条款 | 法国拒绝时 | 法国接受后 |
| --- | --- | --- |
| 释放 TYR | TYR 仍为英国附庸 | 英国与 TYR 的附属关系解除 |
| 转移 LEI | LEI 仍为英国附庸 | 英国与 LEI 的关系解除，法国成为 LEI 的宗主国，类型为 `vassal` |
| 1金币 | 英国及收款国金额不变 | 英国支付1000 raw，即1金币；引擎向法国及其参战伙伴分配款项 |
| 战争赔款 | 英国与法国之间没有赔款关系 | 英国向法国赔款，期限为1455.6.18至1465.6.18 |
| 战争 | 法英战争继续 | 法英战争结束，已回应的目标提议从待处理队列移除 |

实际金币分配为：法国690、AMG 62、AUV 14、BOU 69、FOI 57、ORL 108 raw，合计1000。金额来自结算函数前后的同日观测；批次跨过一次月结，不能直接把批次开始与结束的国库差额全部归于和约。

英国原生 AI 拒绝的是法国主动提交的要求。法国的两次明确选择使用操作员准备的英国让步提议，经原生条件检查、构造、传输和待处理队列到达法国。法国拒绝第一份，等待外交官冷却后接受第二份。界面玩家保持葡萄牙，桥接回应国家为法国。

## AI 如何调用

先从当前会话的战争发现查询取得 `war_id`，再把完整条款传给 `inspect_diplomatic_action`。下面的要求方向由法国发起，英国履行条款：

```json
{
  "peace_context": {
    "war_id": "从当前会话取得",
    "direction": "demand",
    "terms": [
      {"action_id": "demand_ducats", "amount": "1.0", "payer": "ENG", "claimant": "FRA"},
      {"action_id": "war_reparations", "payer": "ENG", "claimant": "FRA"},
      {"action_id": "release_subject", "country": "TYR"},
      {"action_id": "transfer_subject", "country": "LEI"}
    ]
  }
}
```

本批使用 `action_id=release_subject`、`actor=FRA`、`recipient=ENG` 查询和提交这份组合。`country` 表示附属国；同一族选择多个国家时使用 `countries` 数组，每族最多16国，不能同时提供两个参数，也不能把同一国家同时释放和转移。

本次查询中，两族候选均为 LEI、TYR；选中释放 TYR、转移 LEI 后，整份和约通过原生合法性、发送条件和包装器检查。释放条款的原生费用增量为5，转移为4，整份和约总费用原值为20。费用尺度仍按原始数据标记。引擎还返回接受总值−100和9项中文因素，包括战争分数、和约价值、首都控制、战争持续时间和双方实力；接口保留原值，不把总值换算为概率。

`execute_diplomatic_action` 用唯一请求号提交，并按最新游戏状态重新检查。外来和约用 `peace_offer` 及观察到的 `proposal_id` 执行 `accept` 或 `reject`。`get_diplomatic_result` 返回实际回应和每项条款的后果。

## 场景与原生实现

实验场景从 R51d 独立副本准备：保留英国与 TYR 的附庸关系，增加英国与 LEI 的附庸关系，并给英法设置时代能力 `ab_transfer_vassal_wargoal`。该能力提供游戏原生的转移附庸条件。国家保存字段由原生保存函数确认，正确场景使用根 `countries` 中的国家块，并由另一套既有扫描器核对。实际查询取得转移候选，随后真实结算完成转移。

新增 EXEC9/QUERY17 沿用已有议和上下文和选择流程，分别附加两族国家列表。原生接线复用条款候选、选择、复制、规则与正常执行路径。结果记录原宗主关系和新宗主关系的前后状态、附属类型、金钱、赔款以及战争状态。

本批实际运行使用 B 构建，PID36940，会话 `36940-1dd5f77ab3c60dc`，DLL SHA-256 为 `dfb64aa630f7352c435abf6d69e1e368742c0fde3c58d917e91ee7cb13fdef7d`。游戏从暂停的1455.5.17正常推进到1455.6.18，等待时间由原生外交官冷却提示确定。

## 运行发现的问题与修正

本批有四类实际缺陷。

1. 场景生成器把时代能力写入了全局顾问列表中的同名国家块。国家范围在闭合后未清除，生成器自己的验证重复了相同错误。通过国家块只有31行这一异常及独立范围读取，定位并修正为场景002；错误场景001保留且从未载入。
2. 组合回执的参数缓冲仍为1000字节。按声明边界填充的独立格式化用例复现了 JSON 截断；扩为2048字节后，同一输出1322字节且解析成功。结果事件缓冲也改为按实际内容容量分配。
3. Python 把两项附属国条款计入旧版规则计数，并在请求恢复的动作名单和第二次回执投影中漏接了新条款。前者让真实可用查询显示为未知，后者让已被英国拒绝的请求停在已提交。两处均使用原事件修正；遗漏的两个回执字段由原生回执补回，并保留修正前日志副本及更正记录。
4. 原生附属条款的汇总标志从假开始累积，导致每项关系后果都验证成功而 `terms_verified` 仍为假。原生源代码已修正初始化。B 构建原始事件保留该假值；公开结果独立严格核对本次全部关系前后值、金钱与赔款后返回 `terms_verified=true`，同时保留 `native_terms_verified=false` 和 `terms_verification_source=validated_native_effects`，说明汇总来源。

这些修正复用了已经取得的查询、回执和后果，没有重放已完成的外交业务。
