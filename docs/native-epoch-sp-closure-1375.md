输出 `work/reports/native-epoch-sp-closure-1375.json`。本轮新增 23 个有界 CFG，连同一个区域扫描共解码 83,222 字节；上限 192 KiB / 48 个新增 CFG，内存守卫 768 MiB。全可执行节只做指定字节模式检索，没有整文件反汇编。报告把未验证的字节候选与经过 CFG 验证的指令分开。

## 世界与国家数组

`74dd50 → 286250` 不是唯一国家数据库销毁路径。已验证的全部直接 E8/E9 调用为：

| 目标 | 调用者 / 调用点 | 含义与失效时机 |
| --- | --- | --- |
| `74dd50` | `74bf70 / 74bff2`、`74d890 / 74d89f` | 派生或基类游戏析构；派生路径在到达这里前已清上下文成员 |
| `286250` | `74dd50 / 74ddc3`、`1fefa0 / 1ff572` | 应用清理独立检查数据库并销毁；不能只挂游戏析构 |
| `2830a0` | `207310 / 207752`、`208620 / 20b315` | 重置后与启动时建立 country block / pointer index |

应用清理的 `1ff563` 读取数据库全局，`1ff56d` 对空值分支，`1ff572` 析构，`1ff57f` 释放，`1ff584` 清全局。早先的游戏析构同样有条件分支。因此应在 `1fefa0` 入口撤销，`286250` 作为仅匹配已绑定数据库的后备；后者对整个应用清理的其他对象已不够早。

数据库构造 `2812a0` 在 `2812e0 / 2812f5` 清 `+108 / +118`。建立国家的 `2830a0` 在 `283143` 写新 `+108`，在 `283181` 以 `RCX=database+110` 调用通用容器扩容 `8f4f0`。该函数复制旧元素，调用容器虚槽 `+10`，再在 `8f542` 写新的容器 `+8`，即 database `+118`。已固定的数据库索引虚表 `1c38348+10 → 8f4c0` 释放并清这个指针。

因此，可实现的增量是：`2830a0` 在绑定数据库上执行时提前撤销；任何 `2812a0` 出现在已授权会话期间也可保守撤销，接受假阳性，不把每次构造都称作读档。若为共享容器函数加后备，必须只匹配 `RCX == bound_database + 0x110`，不能把所有容器扩容视为世界切换。区域 `280000..28a000` 的 82 个 pdata 函数、39,331 字节检查中，真正 block/index 的直接写主要落在构造、建立、析构；同位移的栈变量和其他类候选均未提升成数据库写入证据。

全可执行节的指定 RIP-relative MOV 编码共找到 764 个候选：3 个 game-global 写、761 个 database-global 写。后者中 759 个在 24 字节内紧邻 `2812a0` 的调用字节模式；另外两个是 `1ff584 / 74ddd7` 清零。**这 759 个是有限字节模式归类，未逐个证明其分支和对象来源。**它们说明到处内联的惰性初始化不能靠只盯两个调用者封闭；不证明任意 bulk store、寄存器别名或间接调用不存在。

沿用前报告的早期失效入口：`1fefa0 / 210000 / 74b8a0 / 5cf740 / 749020 / 74bf70 / 74dd50`。`74a260 / 74c080 / 2812a0 / 2830a0 / 286250` 是逻辑清空、创建与销毁的后备。`2e1a30` 还用于正常动态国家建立，需要国家 incarnation，或保守全会话撤销。这个集合覆盖已审查的有限路径，尚不是已证明最小的全程序切集。

## 单机来源与同址网络变化

`80b4c0` 只有一个已验证直接调用 `803d27`，目的对象是 server `+1708`。它把 config `+2e8/+2e9` 复制为 server `+19f0/+19f1`。赋值函数 `ad6a70` 的三个已验证直接调用仍是两条网络前端路径与 SP Play 路径。对运行 server 区域中的 `19f1` 字面位移候选解码，得到的是读或比较；没有新增该字段写入证据。`83a4f0` 还会返回 server `+1708` 的地址，其两个直接调用只读名字，但这不构成配置无别名写入的全程序证明。

更关键的是，会话生命周期可以不改 `19f1`：

* `80fee0` 读 `19f1`，先通过 transport 虚槽 `+18` 关闭，再两次调用 `811ab0` 清上下文并安装新 type2 上下文；不写 `19f1`。
* `80fc90` 同样先关闭 transport，再调用上下文状态分派 `14ca360`。
* type2 transport 的 `+18 → 1574fb0` 只有 12 字节：`RAX=[RCX+70]`，写 `[RAX+48]=0`。server、context、transport 三个地址可都不变化，而上下文状态已经改变。
* type0 的 `157c620` 也清 backlinked context `+48`；type1 的 `1577280` 进入平台/session 的虚函数关闭路径。不能把这些关闭函数的每次调用都命名为“迁移”，但它们足够构成授权来源失效事件。

所以 `19f1==0` 仍应作为必需拒绝条件之一，**不能当迁移计数器，也不能单独判严格单机**。`6eaa10=false`、context/transport 虚表存在、所有地址没变，都没有补上这项证明。

## 四个原失效点的边界

| 入口 | 已覆盖 | 明确遗漏 / 建议后备 |
| --- | --- | --- |
| `811ab0` | holder `+370` owning pointer 替换前 | 调用它前可能已执行 transport close；补绑定 transport 的 `1574fb0 / 1577280 / 157c620` 入口 |
| `14c9930` | 重置、关闭与重新初始化前 | `838dc0` 可直接调用 `14cd4d0`，绕过它 |
| `14c97e0` | 此初始化函数内部字段变化前 | 位于 `14c9930` 的 close/reset 之后，不替代上层入口 |
| `14cd8b0` | 自身的同址 transport 替换前 | `14ca360` 会先清 pending `+840`、调用通知虚函数；重入/并发边界未闭合 |

`14cd4d0` 清理 context `+158` 的 owned list 并清 `+158/+160/+168`。`838dc0 / 8395e0` 可以直接调用它后清 `+841`；列表的确切语义类型本轮没有命名。它可作为保守 session-origin 撤销点。context 虚表 `1d8c900+0 → 14c88f0 → 14c99c0` 则提供独立析构后备。

不能无条件把 `14ca360` 每次进入都称作迁移：它是普通状态分派。仅在入口检查 `+840` 也不足以证明完整性，因为它随后有 transport 虚调用，再次检查并处理 pending 状态；通知还可能早于 `14cd8b0`。这项重入与线程同步缺口继续阻挡 production。

## 可实施守卫与尚缺的验证

未来实现应从 `REVOKED` 开始，在已证明的 SP 前端选择、配置 `(1,0)`、上下文安装、运行服务器构造序列中建立新的 origin witness。晚注入的适配器不能用当前字段倒推这段历史。每个相关入口先原子撤销 readiness 和排队授权、递增 generation，然后才交还原生函数；返回成功或失败都不恢复旧世代，也不回收已经消耗的 attempt claim。

上下文、transport、容器后备只能与事先绑定的身份比较；不能先跟随可能已释放的指针再决定是否撤销。每次执行前仍核 exact module、原生线程、完整国家 handle、game/database/block/index/server/holder/context/transport 身份、配置 `(1,0)`、type/flags/transport 组合、backlink、pending 状态；以 generation 双读排除采样期间失效，并在转交所有权前再核一次。

**generation 双读不等于并发内存安全。**如果别的引擎线程可能在原生调用期间销毁对象，还需要证明同一主线程串行化或正确的引擎锁。当前尚未证明全部间接写入与调用、所有读档前置路径、通知重入、worker 同步、hook 安装与异常覆盖；未实现或运行上述 observer。报告中的前缀和字节锚只是下一轮实现与独立审查的输入。
