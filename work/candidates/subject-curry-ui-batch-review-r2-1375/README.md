This is a fixed, bounded file reviewer. It does not open a process, invoke a
native function, operate UI, publish requests, or change capabilities. Root's
manual batch used FRA with BUR/NAV/POR in the exact order set_rival,
military_focus5, embargo_rivals on, scutage on, divert_trade on, curry_favors on.
The journal is manual observation, never a native-authenticated receipt.

The fixed identity is PID38232, creation01dd56e0cbe2c7f7,
world0x1a0cb39c020 and rawdate56456976. Every report must be a complete held-RO
report. A fixed case supplies exactly the initial/final census and stopped

## What is recomputed

- Curry and toggle reports pass their original typed capture validators, with
  both complete snapshots and stored selections checked. Focus passes its
  original typed snapshot inspector; its producer stores one raw snapshot and
  a boolean assertion of an equal second pass. The unrecorded second focus
  pass is not invented or treated as independent memory authentication.
- Each source's bounded read trace is reconciled with its declared calls and
  bytes, preserving its original8192-call/16MiB limits. These are separate
  sampler budgets, not a fictional shared atomic reader. The three reports
  bind identical held PID/full creation/module/EXE rights, common world roots,
  full FRA handle/country object, count, date and reset/load fields. The two
  target objects must differ. Focus's entire snapshot must equal toggle.graph
  within each census.
- Across the batch, the original focus comparison fixes the complete subject
  graph except focus0→5. Toggle singleton registration and permission map
  remain identical. Only the three selected flag bits change0→1; unrelated
  subject flags cannot change. Actor presence/marker and subject-at-war stay
  equal. Rival_count is explicitly0→1. This real change means the old toggle
  same-state comparator is unsuitable; it is not bypassed and then claimed
  successful. Both before/after states are independently validated, and this
  reviewer declares its narrower batch comparison.
- Curry uses the original held-capture comparison. Before must have complete
  selected relation/mission absence; after must have exactly one active,
  direction- and full-handle-bound relation/mission/entry graph, started on the
  fixed day. Unknown types, orphan/returning missions or an index alone cannot
  pass. The final state does not prove favorable opinion, an amount of favors,
  or a later cancellation.
- The journal has exactly start plus six alternating intent/ui_confirmed
  pairs with strict boolean versus integer requested values. No unavailable,
  unknown, duplicate, reordered or missing action can pass. BUR is the manually
  recorded rival target; these samplers expose a rival count, not the rival
  target array. `rival_target_ro_verified` therefore remains false.

All native receipt/authorization, interface execution, individual causal
effect, side effects, strict SP, epoch/lifetime, whole-world preservation,
save/reload and production claims remain false. The observations are selected
state changes across one manual batch. Groups were not sampled atomically.
`game_native_calls=false` describes the sampler, not UI-triggered game actions.
Exact disk EXE SHA is distinguished from full loaded image hashing.

## Bounds, sources and validation

`input-pins.json` pins the three reviewed observer implementations, reports,
independent reviews, pure fixture sources and the two fixed producer helpers.
Its SHA is compiled into reviewer.py; source-index.json binds this candidate.

nonfinite values are rejected. All three inputs are hashed before decode and
again before a CREATE_NEW output. Existing output files are never replaced.

then attach explicitly synthetic held identities. No actual census or OS
