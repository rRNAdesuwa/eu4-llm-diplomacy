## AI 如何使用

| 动作 ID | 作用 | 阶段与参数 |
| --- | --- | --- |
| `set_rival` | 把目标加入行动国的宿敌列表 | `phase="initiate"`，`parameters={}` |
| `remove_rival` | 从行动国的宿敌列表移除目标 | `phase="initiate"`，`parameters={}` |

四个统一入口分别负责发现动作、查询当前条件、提交唯一请求和读取结果：

```python
candidate_country = "BUR"
catalog = api.list_diplomatic_actions(actor="FRA", recipient=candidate_country)
inspection = api.inspect_diplomatic_action(
    "set_rival", "FRA", candidate_country, phase="initiate", parameters={}
)
if inspection["legality"]["status"] == "available":
    submission = api.execute_diplomatic_action(
        request_id, "set_rival", "FRA", candidate_country,
        phase="initiate", parameters={}
    )
    result = api.get_diplomatic_result(request_id)
```

每个请求编号只代表一次确定选择。重复读取已执行请求会得到已有结果。已发布但结果未知的请求继续按原编号查询；操作器保存原生日志和持久请求记录，方便恢复结果读取。

## 如何理解查询结果

查询把接口能力、桥接授权和游戏合法性分别输出。[G 公共字段验收](../work/runtime/diplomacy-query-20261016-r34-rival-g-reload/public-projection-validation-001/report.json)实际覆盖以下情况：

| 查询 | 接口与授权 | 游戏合法性 |
| --- | --- | --- |
| 再次移除 CAS | 执行适配已实现，FRA 授权可用 | `unavailable`，目标已经不是宿敌 |
| 再次宣布 BUR | 执行适配已实现，FRA 授权可用 | `unavailable`，目标已经是宿敌且名额已满 |
| 移除现有 ENG（英格兰） | 执行适配已实现，FRA 授权可用 | `available`，当前原生条件通过 |

`relationship_state.rival_active` 回答目标是否已经是宿敌。`native_command_validity` 是原生命令条件结果。设置宿敌还需要目标存在、通过原生候选检查、拥有空余名额并满足和平条件；移除宿敌还需要目标确实在列表内、保留期限已满且外交点足够。schema3 将这些条件联合为 `native_action_available`，通过全部调用后输出 `full_rules_complete=true`。原生诊断提供的原因数量另外保留完整性标记。

例如 R34D 中 BUR 和 SAV（萨伏依）都不是宿敌，但 Remove 的原生命令条件曾返回 true。成员关系检查会阻止这两个无效移除请求。R34D 的 ENG/CAS 移除条件因五年保留期限未满而禁止；实验自然推进到 1449.11.17 后，CAS 条件通过并实际完成移除。

已核验的移除费用公开为 `amount=101`、`amount_raw=101`、`unit="diplomatic_power"`、`scale=1`。已知费用条目完整；`coverage.additional_costs="unknown"` 表示尚未穷举其他附加费用，和动作是否合法分别记录。

## 本轮发现并修复的问题

第一次 Remove 的原生提交和业务执行都成功，Python 却因读取 `flags/sequence` 而拒绝 DLL 输出的 `native_flags/native_sequence`。修复后，结果回收器验证唯一提交回执与实际执行事件，将原请求恢复为 `executed`，并追加审计证据。原失败报告保留，[幂等回读](../work/runtime/diplomacy-query-20261016-r34-rival-f-mature/rival-reconcile-634bd7466c8a49cbb0c75174869c0b52/readback-report.json)确认没有重复发送。

保存脚本还遇到自动存档轮转期间文件暂时消失的情况。脚本现在等待新的稳定文件，并在候选消失或失效时重新计算稳定时间。本轮组合存档已使用修复后的脚本成功保存。启动确认探针现在沿已知 UI 对象路径定位窗口，关闭私有堆扫描；G 实际安装读取了已验证的确认窗口。
