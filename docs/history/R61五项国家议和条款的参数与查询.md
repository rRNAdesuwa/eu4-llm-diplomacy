这五项条款分别是释放国家、强迫附庸、建立共主邦联、承认独立和完全吞并。它们都放在 `peace_context.terms` 中，由 native 检查候选、合法性、费用和结算；Python 层负责确认公开字段的形状、角色和方向。

## 先确定双方角色

调用方仍需提供议和接口的 `actor`、`recipient` 和 `direction`。方向决定两个默认角色：

| `direction` | `offer_payer`：承担条款的一方 | `claimant`：获得条款收益的一方 |
| --- | --- | --- |
| `demand` | `recipient` | `actor` |
| `offer` | `actor` | `recipient` |

例如，`actor=FRA`、`recipient=ENG` 时，`demand` 把英国视为承担条款的一方、法国视为索取方；`offer` 则把法国视为承担条款的一方、英国视为索取方。`source` 和 `beneficiary` 的默认值都按这两个角色计算，native 仍会根据实际战争和国家关系判断请求是否合法。

## 五项条款的参数

| `action_id` | `country` 表示什么 | `source` 或 `beneficiary` | 默认值与结算对象 |
| --- | --- | --- | --- |
| `release_nation` | 被释放、获得国家身份的目标国家 | `source` 是交出该国家省份的一方 | `source` 缺省为 `offer_payer`；native 读取目标国家从 `source` 获得的省份变化 |
| `force_vassalization` | 被强迫成为附庸的国家 | `beneficiary` 是新的宗主国 | `beneficiary` 缺省为 `claimant`；结果读取双方关系和实际 `subject_type` |
| `form_personal_union` | 成为共主邦联次要成员的国家 | `beneficiary` 是共主邦联的主要成员 | `beneficiary` 缺省为 `claimant`；结果要求实际关系类型为 `personal_union` |
| `grant_independence` | 不由调用方填写 | 没有公开 `country`、`source` 或 `beneficiary` 字段 | 只写 `action_id`；生产 bridge 按方向记录 `country=expected_claimant`、`overlord=expected_payer`：`demand` 时 claimant=actor、payer=recipient，`offer` 时相反。`country` 是 claimant 的结果投影，不是调用方填写的独立国家参数 |
| `full_annexation` | 失去全部可吞并省份的国家 | `beneficiary` 是接收全部省份的一方 | `beneficiary` 缺省为 `claimant`；native 自动要求目标国家的完整候选省份集合，不能只提交部分 `province_ids` |

R61 已实际运行的组合请求使用真实战争上下文，而不是把五族条款硬拼成一个未验证例子。法英组合的请求是：

```json
{
  "peace_context": {
    "war_id": "war_8a21761489dcf8d7_00000001",
    "direction": "demand",
    "terms": [
      {"action_id": "release_nation", "country": "FLY", "source": "ENG"},
      {"action_id": "full_annexation", "country": "TYR", "beneficiary": "FRA"}
    ]
  }
}
```

该请求由 `actor=FRA`、`recipient=ENG` 发起，组合查询、英国原生拒绝以及随后法国拒绝/接受同一份 pending 的证据见[组合执行报告](../../work/runtime/r61-country-combined-execution-d-20261019-001/report.json)。

附庸条款使用另一场真实 FRA→LEI 战争的单条款请求：

```json
{
  "peace_context": {
    "war_id": "war_2b6fca14f030910c_00000001",
    "direction": "demand",
    "terms": [
      {"action_id": "force_vassalization", "country": "LEI", "beneficiary": "FRA"}
    ]
  }
}
```

这份请求的 `actor=FRA`、`recipient=LEI`；接受后 FRA→LEI 的关系从无到有、`subject_type` 从 `null` 变为 `vassal`，并报告 `terms_verified=true`、`war_after=false`、`pending_removed=true`，见[附庸执行报告](../../work/runtime/r61-country-vassal-execution-20261019-001/report.json)。共主邦联沿用同一对国家的单条款形状，把 `action_id` 改为 `form_personal_union`；其真实执行报告见[共主邦联执行报告](../../work/runtime/r61-country-union-execution-20261019-001/report.json)。

承认独立的公开请求保持无参数的 `{"action_id":"grant_independence"}`。在真实独立战争中先由[宣战执行报告](../../work/runtime/diplomacy-query-20261019-r61-country-independence-g/declare-war-execution-4ee3e01a39a34856b479fc82c1e819fc/report.json)记录 ENG→FRA 的独立战争；随后同一条款完成原生拒绝、法国拒绝和法国接受。接受结果中的 `country=FRA` 来自 claimant，`overlord=ENG` 是原宗主，调用方没有填入 country；前后宗主数量均为0，扫描完整且 `no_other_overlords=true`，并报告 `terms_verified=true`、`war_after=false`、`pending_removed=true`。完整证据见[承认独立执行报告](../../work/runtime/r61-country-independence-execution-20261019-004/report.json)，终态文件为 `llm_diplomacy_peace_country_independence_accepted_20261019_r61.eu4`。

较早的003场景曾返回 `native_state=2`，但接受后仍保留 vassal 关系，因此 `terms_verified=false`；该结果作为失败证据保留，没有重做或把它算作成功。

完全吞并与割让省份的参数含义不同。完全吞并只指定 `country` 和接收方，native 先枚举该目标国家当前全部可用的吞并候选，再要求候选集合与目标国家的全部省份对应。候选不完整时，查询应报告不可用或不完整；程序不能静默截断为一部分省份。

承认独立也有意不接受 `country`。生产 bridge 的 public context 将 `grant_independence_country` 规范为 `expected_claimant`，将 `grant_independence_overlord` 规范为 `expected_payer`：`demand` 时 payer=`recipient`、claimant=`actor`，`offer` 时 payer=`actor`、claimant=`recipient`。native 仍负责当前宗主关系的合法性和实际结果；Grant004 已在真实独立战争中核对这两个角色，接受后的 claimant 是 FRA、原宗主是 ENG，且宗主全量扫描为完整的0项。

## 查询、执行和结果

查询分两步完成。先用空的 `terms` 发现该条款在当前战争中的候选；再把选中的条款放入 `terms`，查询整份和约：

```python
inspection = tools.inspect_diplomatic_action(
    "full_annexation", "FRA", "ENG",
    parameters={
        "peace_context": {
            "war_id": war_id,
            "direction": "demand",
            "terms": [
                {"action_id": "full_annexation", "country": "TYR"}
            ]
        }
    },
)
```

空 `terms` 表示候选发现，不代表程序已经选择了一项；选择后的查询才会返回这份参数对应的原生合法性、费用、接受因素和条款候选。接口保留 `unknown`、`unavailable` 与 `available` 的区别：`unknown` 表示还需要候选或上下文，`unavailable` 表示 native 已完成检查并拒绝当前请求。

查询通过后，`execute_diplomatic_action` 使用同一份 `peace_context` 提交一次请求。执行层不会根据 `action_id` 猜省份、宗主或受益国，也不会自动改写第三国角色。`get_diplomatic_result` 读取实际回应：接受或拒绝由对方/native 决定，条款后果则来自 before/after 状态读取。国家条款的结果包括：

- 释放国家和完全吞并：目标与来源/受益方的拥有省份数量，以及每个相关省份的 owner、controller 前后值；
- 强迫附庸和共主邦联：关系是否存在、是否为宗主方，以及存档中的实际 `subject_type`；
- 承认独立：以 claimant 和原宗主为绑定角色读取关系字段，并对其他宗主关系做完整扫描；Grant004 接受后扫描前后均完整、宗主数量均为0且 `no_other_overlords=true`，因此结果为 `terms_verified=true`，而不是把未知当成独立已经完成。

拒绝结果仍读取真实后状态。它可以显示条款未改变，也可以显示原生拒绝分支产生的其他变化；验证器不预先假定所有拒绝都会保持原值。

## 一次批次与终态保存

同一战争、同一游戏进程中，可以先集中完成多项候选查询，再按依赖顺序把兼容条款组合成一份和约。组合查询只做一次整份和约的合法性与费用判断，提交也只做一次；执行后集中读取公共结果和条款相关字段。互斥条款应拆到所需场景中，不能为了减少查询而把原生不允许的条款硬塞进同一份和约。

终态保存字段用 before/after 流式核对器检查，不把整份存档加载成内存对象，也不从跨月国库差额推断金钱结算。R61 对应工具是 [`work/compare_r61_country_save.py`](../../work/compare_r61_country_save.py)，输入为两份存档和实际角色列表：

```powershell
python work/compare_r61_country_save.py `
  --before baseline.eu4 `
  --after accepted.eu4 `
  --expectations '[{"action_id":"release_nation","country":"TYR","source":"ENG"}]' `
  --output work/runtime/r61-country-save-fields-001
```

工具只保留目标国家相关省份的 `owner/controller` 和 diplomacy 直接附属关系块。释放国家至少要看到 `source → country` 的省份转移且目标拥有省份增加；完全吞并要求目标拥有省份变为零，并逐一核对原目标省份转给 beneficiary；强迫附庸和共主邦联核对实际关系类型；承认独立要求目标没有直接宗主关系。当前工作流按批次集中核对终态保存，不为这五项另设专门重载进程。
