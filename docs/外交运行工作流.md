# 外交运行工作流

本规则用于安排批量外交运行，同时保留原有的 19+19 条验收范围。当前流程不再安排专门的存档重载验收；批次统一准备和查询若干操作，按依赖串行执行，再集中读取结果和保存字段。历史重载证据继续保留，减少的是重复流程，不是业务、规则、接口或权限验收。

## 每轮按触发条件安排检查

| 触发 | 必做检查 | 可以省略或复用的内容 |
| --- | --- | --- |
| 同一安装、同一 DLL 的多项操作 | 批量开始和结束各做一次 control；统一准备和查询；按依赖串行执行；结束时集中读取结果和保存字段 | 不为每个 case 各做四类完整快照；协议和权限未变时复用已核对的历史负例 |
| 同批条款能够兼容 | 尽量放入同一份和约，统一核对条款、角色、结果和保存字段 | 互斥操作按所需情境排序或分组，不为组合关系重复建立整套流程 |
| 启动既定实验存档 | 只把存档启动作为建立实验场景的一步，并完成本批次所需的初始 control | 不另安排专门的回读进程或重载验收；历史重载结果保留作已有证据 |
| 只改 Python 投影、校验器或保存解析 | 针对改动做一次定向测试，并用保留的原事件或观测离线纠正 | 不因投影或 checker 修复重启游戏；适配稳定后再做一次全套回归，只有新改动或新失败才增加测试 |
| 真实事件消费或 validator 出现问题 | 保留原始事件、请求和观测，离线重算公开结果并记录修正原因 | 不重放已经完成的外交业务；若原生事件本身缺少证据，再补具体的原生检查 |
| 批次结束或真实代码发生改动 | 批次一次性完成快照、定向测试或回归、源码 hash、证据索引和归档 | 不在每个操作后重复这些工作；缓存 hash 由 Python worker 单独维护 |
| 任意阶段的资源检查 | 大文件只做有界流式读取，继续禁止逐步整机 RAM 巡检和整份大型反汇编读取 | 这条限制没有例外 |

同一构建产生多个保存分支时，可以串行放入一个批次。新 DLL 安装使用新进程；同场景多操作复用该进程；场景切换统一准备，不为保存结果验收另开回读进程。只改 Python 投影或 checker 不要求重启进程。批次开始和结束的 control 用来确认环境没有意外变化，业务结果和保存字段集中读取，覆盖该批次实际影响的国家、战争、关系或数值。R57 已在同一进程完成 14 项核心条款查询；公共接受因素漏投影后，直接使用原事件离线修正，58 项检查通过。

缓存 hash 由 Python worker 单独维护；本政策不要求为减少重复检查而修改这部分代码。

## 启动窗口停滞与查询验收

R65 遇到过游戏渲染线程等待 D3D/DWM、载入确认长期不出现的问题。启动器现在每3秒探测一次场景；连续3次明确找不到载入确认后，只对当前进程唯一核实的游戏窗口执行一次最小化和恢复，再继续原来的载入流程。短暂的进程身份读取错误仍按1秒重试。窗口恢复只执行一次，也不触发整机内存检查。

批量报告需要区分“取得了费用预览”和“所请求的条款已选中”。每个必验动作必须有对应的原生事件、请求参数校验、公开投影及前后状态比较；接口错误或事件缺失应使批次结论变为部分完成。游戏明确禁止某项条款可以作为规则负例，但该结果需要保留原生原因。不能只检查已经返回结果的子集，再把整个动作清单标为通过。

## 保存字段与历史重载证据

当前流程取消专门的存档重载验收。一次批次先统一准备和查询，再按依赖串行执行若干外交操作，最后集中读取原生结果与保存字段。新 DLL 安装使用新进程；同场景多操作复用该进程；场景切换统一准备，不为保存结果验收另开回读进程。启动既定实验存档只建立场景，不自动追加回读进程。最终报告仍逐项列出已取得的运行时、结果和保存字段证据，以及历史上已经取得的重载证据；缺少哪一项就明确记录，不用新重载替代其他验收。

保存读取和重载曾经实际帮助定位问题，也曾经暴露检查器问题，二者需要分开描述：

- R56 的战争保存中没有读到请求的 CB/goal。直接流式读取保存就发现了这个实验背景的证据缺口，不需要重启；脚本成功创建战争不等于引擎已经按请求载入目标。
- R54 接受结果的重载探针把羞辱记录读成了错误国家角色。原生结果和保存没有因此改变，错误在探针读取角色，接受样本中胜方名单与败方名单的非对称内容才使它显现。
- R56 重载中的声望检查并不适用于宗教条款，要求所有 pending 为空也错误，因为法国还保留另一份自然提议；保存宗教比较则漏读了目标首都省份的 `religion` 字段。这些是 checker/parser 的错误，修正后才比较实际保存值，不能写成游戏没有保存结果。

这些案例不支持“保存永远不会出错”的结论。历史重载证据保留，新的保存字段问题仍由当前批次的有界读取和结果比较发现；本流程不因某个后果首次成功、pending 恢复或布局变化自动安排重载，也不把这项调整理解为减少其他业务、规则、接口或权限检查。

## 仍然完整的交付范围

流程调整不改变 19 项常用外交、19 项常用议和条款、统一四入口、原生规则复用、受控国由 LLM 决定、非受控国保留原生 AI 权限，以及执行结果、保存字段和证据索引的完整记录。兼容条款尽量在同一份和约中验证；不兼容条款按依赖和场景分组，仍分别取得可用、不可用、未知、接受、拒绝和实际后果。
