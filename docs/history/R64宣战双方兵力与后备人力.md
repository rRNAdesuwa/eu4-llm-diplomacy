# R64：随参战选择重新计算双方兵力与后备人力

更新：2026-10-19。

AI 现在可以通过 `inspect_diplomatic_action` 同时查询宣战双方的国家名单、已部署步兵、骑兵、炮兵、部署总人数和后备人力。查询使用当前宣战理由和参战选项；召集盟友、许诺土地或选择敌国联合作战方后，接口重新计算两侧数值。

同一暂停会话完成了 18 个有效查询，覆盖英格兰、勃艮第、摩洛哥和米兰。两个批次共 110 项检查通过，18 个查询的兵力范围与数值均完整。游戏日期始终为 1455.9.10，行动国为法兰西。

## AI 如何调用和读取

```python
result = tools.inspect_diplomatic_action(
    "declare_war", "FRA", "MLO", phase="initiate",
    parameters={
        "casus_belli": "no_casus_belli",
        "war_goal": {"province_id": -1, "beneficiary": "FRA"},
        "call_allies": ["SAV"],
        "promise_land_to": ["SAV"],
        "co_belligerents": [],
    },
)

result["forces"]["attackers"]["deployed"]["total"]       # 76502
result["forces"]["attackers"]["reserve_manpower"]["amount"]  # 172960
```

`forces` 包含 `attackers` 和 `defenders`。每侧的 `countries` 是本次统计覆盖的国家标签；`deployed` 提供 `infantry`、`cavalry`、`artillery`、`total`，`reserve_manpower.amount` 提供后备人力。两类数量的 `unit` 均为 `men`，即人数。

`forces.complete` 表示双方统计完整；每侧还分别提供 `scope_complete`、`deployed.complete` 和 `reserve_manpower.complete`，用于指出国家范围、部署兵力与后备人力是否完整。特殊界面模式未能确定国家范围时，接口会把相应完整性字段设为 false。

宣战合法性继续由 `legality` 单独返回。例如本场景中，勃艮第方向受到最近派遣外交官的冷却限制，合法性为 `unavailable`；同一方案的双方军力仍可完整查询。这使 AI 能在等待冷却期间比较方案。

## 数量来自哪里

宣战窗口原生函数 `ee5430` 按国家部队链累计步兵、骑兵和炮兵的当前兵员。后备人力来自同一国家的 `+0xdb8` 字段。原生窗口第四个累计槽还包含额外单位计数项；接口单独读取后备人力，避免把这些计数项并入后备人力。

四国同日存档提供了单位依据：法兰西、勃艮第、萨伏依和汉萨的 91 个团，按兵种汇总后的存档兵力与原生读数逐项一致；存档 `manpower × 1000` 也与四国原生后备人力一致。例：法兰西部署 29,683 人、后备 44,783 人；勃艮第部署 30,704 人、后备 28,304 人。见[四国存档基线](../../work/runtime/r64-force-save-baseline-20261019-001/report.json)。

最终按 18 个查询的实际国家名单集中读取同日存档，覆盖 37 国、36 个攻守侧。步兵、骑兵、炮兵、总人数和后备人力全部匹配，逐侧检查 432/432、全局检查 11/11 通过，见[双方保存字段核对](../../work/runtime/r64-force-save-groups-20261019-001/report.json)。其中 `mamluk_archer` 的步兵分类还由[游戏单位定义](../../work/runtime/r64-force-unit-definition-20261019-001/report.json)独立确认。

两侧名单复用宣战窗口的自动参战、召集意愿、选中状态和关系判定；选择联合作战方后重新枚举相关候选。统计还展开原生计数函数包含的特定附属国，并用同一国家范围计算部署兵力和后备人力。
