# R59：释放、转移附属国的查询

AI 现在可以通过统一查询接口列出议和中的附属国候选，再指定国家，取得游戏原生合法性、费用和接受因素。`release_subject` 表示要求宗主国解除指定附属国的关系；`transfer_subject` 表示转移指定附属国。两项条款分别保留自己的动作标识和原生对象。

本批在同一进程连续完成10个公开查询，55项检查全部通过。法国要求英国释放 TYR，以及法国提出释放 AUV，均被游戏判定可用。当前战争没有转移附属国候选，两个方向的候选枚举都完整返回空列表。

## 给 AI 的参数与结果

先从战争发现结果取得 `war_id`。把 `terms` 留空，接口会列出相应方向的候选：

```json
{
  "action_id": "release_subject",
  "actor": "FRA",
  "recipient": "ENG",
  "parameters": {
    "peace_context": {
      "war_id": "从当前会话的战争发现结果取得",
      "direction": "demand",
      "terms": []
    }
  }
}
```

选择目标后，把条款写入 `terms`，例如：

```json
{
  "peace_context": {
    "war_id": "从当前会话的战争发现结果取得",
    "direction": "demand",
    "terms": [{"action_id": "release_subject", "country": "TYR"}]
  }
}
```

`country` 是附属国。当前 `demand` 例子要求英国释放 TYR；把方向改成 `offer` 并选择 AUV，表示法国提出解除自己与 AUV 的附属关系。转移附属国使用相同的参数结构，动作改为 `transfer_subject`。

`native_subject_terms.candidates` 返回候选国家、选择状态和记录完整性。选定查询还返回参数是否匹配、复制后选择是否一致以及原生费用变化。公共接口继续分别输出合法性、会话就绪、授权与接受信息。只发现候选时，合法性为 `unknown`，原因是尚未选择条款；指定的国家不在完整候选列表中时，合法性为 `unavailable`。

释放条款另核对了两方向的发现查询和错误目标。费用以 `native_war_score_raw` 输出，尺度仍未核验；接受总值是引擎原值，接口保留中文因素明细。

保存字段说明了候选国家的实际身份：英国与 TYR 的 `dependency` 类型是 `vassal`；法国与 AUV、BOU、FOI、ORL 的类型是 `appanage`。新核对器读取保存中的实际附属关系块，保留类型、双方、日期和行号。对 R51d 与 R58 保存的比较得到6组关系保持不变。它为后续释放、转移执行提供了统一的保存字段核对方式。

## 原生实现与继续执行所需的工作

查询使用游戏创建的条款候选，在临时和约中按既有通用选择流程选中目标，再沿原生合法性、发送条件、包装器规则和接受评价查询。释放附属国使用类型 `0x2d27`、桶19，目标位于 `+0x30`；转移附属国使用类型 `0x35f0`、桶20，目标位于 `+0x22`。新查询协议是 QUERY16，旧安装没有对应能力声明时继续返回查询能力不足。

本次完成 list/inspect 接入和真实查询。下一批接入 execute/result、入站回应及实际附属关系后果；两项新条款的执行能力目前明确保持未实现。常用议和已实际执行的覆盖仍为12/19。

转移候选生成另外要求附属类型允许转移、受益国拥有原生转移附庸能力，并满足首都控制条件。游戏的时代能力 `ab_transfer_vassal_wargoal` 提供 `can_transfer_vassal_wargoal=yes`；后续先建立具备该能力的独立场景，再取得转移条款的正向查询与实际执行。
