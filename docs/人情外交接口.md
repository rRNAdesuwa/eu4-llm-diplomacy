# 人情外交接口

## R74补齐：信任和人力的原生接受度与因素

AI查询换信任或换人力时，现在都能取得原生接受度总值、接受预测及逐项中文因素。实际法国→教宗国为220（使用人情50、好感度170），法国→萨伏依为250（50、200）；两个动作各自独立取值。原生键USING_FAVORS和DIPLO_OPINION与实际reason行的数值已绑定确认。接受度保留原生有符号整数及原生阈值1，读取方可以使用返回的predicted_response。

[8项实际查询](../work/runtime/r74-favor-acceptance-20261020-002/report.json)同时记录正向公开结果和实验私有反向观察。人力兑换的五年冷却在legality中明确说明，接受度仍可单独查询；不会因为冷却而丢失当前因素。R73的六条实际响应及保存证据继续沿用。

人情表示一个国家可以向另一个国家请求回报的外交资源。接口使用 `actor` 表示提出请求、花费人情的国家，使用 `recipient` 表示收到请求的国家。兑换金币或人力时，recipient 向 actor 支付资源；兑换信任时，提高的是 recipient 对 actor 的信任。例如 FRA 向 PAP 换信任，增加的是教宗国对法兰西的信任。

## 派遣外交官获取人情

`curry_favors` 开始向目标国家获取人情，`stop_curry_favors` 停止任务并召回外交官。两项操作都由行动国决定，只需指定双方国家：

```python
inspection = tools.inspect_diplomatic_action("curry_favors", "FRA", "SAV")
result = tools.execute_diplomatic_action(
    "curry_FRA_SAV_001", "curry_favors", "FRA", "SAV")
result = tools.get_diplomatic_result("curry_FRA_SAV_001")

result = tools.execute_diplomatic_action(
    "stop_curry_FRA_SAV_001", "stop_curry_favors", "FRA", "SAV")
```

查询的 `task_active` 表示双方当前是否存在获取人情任务，`task_state_verified` 表示是否取得原生状态；同一状态也列在 `relationship_state`。`resources.diplomats` 提供该操作是否需要空闲外交官及当前可用数量。开始需要可用外交官；停止按原生规则召回正在执行任务的外交官，回到本国后才能重新派遣。

`get_diplomatic_result` 在原生执行完成后返回 `game_outcome=executed`，结果中的 `task_before`、`task_after` 分别说明执行前后的任务状态。重复开始会返回“正在向目标国家获取人情，无法再次开始”，停止不存在的任务会返回“当前没有向目标国家获取人情的任务，无法停止”。对应稳定代码为 `NATIVE_CURRY_TASK_ALREADY_ACTIVE`、`NATIVE_CURRY_TASK_NOT_ACTIVE`，两种非法执行均已验证未提交。

R72 实际连续完成法国向 PAP 开始、向 SAV 开始、向 PAP 停止三次操作，任务状态分别为 false→true、false→true、true→false，结果 journal 重开一致。最终保存中，PAP 对应的外交官从罗马省118返回巴黎省183；SAV 对应的外交官从巴黎省183前往萨伏依省205，任务继续。保存核对器同时读取同一存档的三国首都来判断方向。两条绕过授权的停止尝试也被拦截，SAV 任务保持运行。

查询与执行证据见[八项批查](../work/runtime/r72-curry-queries-20261020-001/report.json)、[三次实际执行](../work/runtime/r72-curry-execution-20261020-002/report.json)、[权限拦截](../work/runtime/r72-curry-authority-20261020-001/report.json)、[非法执行原因](../work/runtime/r72-curry-invalid-20261020-001/report.json)及[独立保存核对](../work/runtime/r72-curry-final-save-20261020-002.json)。当前运行接口提供任务状态；每月人情增益数值仍需补充原生计算来源。

## 用人情换信任或人力

两项动作均使用游戏提供的默认兑换量，调用者指定双方国家即可。

| 动作标识 | 查询中的资源 | 接受后的变化 |
| --- | --- | --- |
| `trade_favors_for_trust` | `favor_trade.trust`、`favor_trade.amount` 和人情费用 | recipient 对 actor 的信任增加原生增量，上限100；actor 持有的人情扣除原生费用 |
| `trade_favors_for_men` | `favor_trade.manpower`、`favor_trade.amount` 和人情费用 | actor 获得原生计算的人数，recipient 减少相同人数；actor 持有的人情扣除原生费用 |

```python
inspection = tools.inspect_diplomatic_action(
    "trade_favors_for_men", "FRA", "SAV")
result = tools.execute_diplomatic_action(
    "favor_men_FRA_SAV_001", "trade_favors_for_men", "FRA", "SAV")
result = tools.get_diplomatic_result("favor_men_FRA_SAV_001")
```

查询统一返回 `favor_trade` 和 `costs`。人情按1000缩放，信任按整数点、人力按人数返回。信任使用 `trustor`、`trusted` 明确方向；人力使用 `payer`、`receiver`。例如 `trustor="PAP", trusted="FRA"` 表示教宗国对法兰西的信任。

收到外来请求时，从动作目录的 `incoming_proposals` 取得 `proposal_id`，再按下文的 `accept` 或 `reject` 调用。实际接受结果提供资源的执行前值、执行后值和差额；实际拒绝结果核对信任或人力及人情保持原值。

## 用人情换金币

动作标识是 `trade_favors_for_gold`。兑换金额和人情费用由游戏的原生规则计算，调用者只选择双方国家。

```python
inspection = tools.inspect_diplomatic_action(
    "trade_favors_for_gold", "FRA", "PAP")

result = tools.execute_diplomatic_action(
    "favor_gold_FRA_PAP_001", "trade_favors_for_gold", "FRA", "PAP")

result = tools.get_diplomatic_result("favor_gold_FRA_PAP_001")
```

查询结果的 `favor_trade.amount` 包含兑换金额、单位、付款方和收款方；`favor_trade.favors` 包含当前可用人情和本次费用。数值同时提供原始整数与按比例换算的值，金币和人情的比例均为 1000。`costs` 也列出人情费用，供调用者与其他外交操作统一比较。

`legality` 给出当前游戏规则的判定，`authorization` 给出桥接是否允许当前受控国家执行该操作。原生规则会检查发送冷却、对方战争和附属关系、收入、支付能力、破产、意见、人情以及通用外交条件。需要外交官时，统一接口还会返回外交官需求与可用数量。执行入口会使用执行时的最新状态复查。

`acceptance` 单独说明原生接受度是否适用、是否取得总值及因素。对方是否接受，最终由对方实际作出的响应决定。非受控国家继续使用游戏原生 AI。

每次新业务使用新的请求编号。重复读取使用 `get_diplomatic_result`；再次提交相同请求编号会读取原请求结果。

## 接受与拒绝外来请求

当外来金币、信任或人力兑换请求的接收方是受控的 FRA 时，桥接保留提议，交给 LLM 选择。LLM 从入站提议列表取得公开的 `proposal_id`，再查询或响应对应提议：

```python
inspection = tools.inspect_diplomatic_action(
    "trade_favors_for_gold", "SAV", "FRA", "accept",
    {"proposal_id": proposal_id})

result = tools.execute_diplomatic_action(
    "favor_gold_inbound_001", "trade_favors_for_gold", "SAV", "FRA", "accept",
    {"proposal_id": proposal_id})
```

拒绝使用 `reject` 阶段。查询和响应都绑定原提议、双方国家及当前会话；提议失效后，接口返回对应状态。

## 读取实际结果

`submitted` 表示请求已经进入原生投递链。`game_outcome` 在取得实际响应后变为 `accepted` 或 `rejected`，`favor_trade` 列出金币转移量和人情变化。

接受结果需要同时核对三项变化：请求方收到原生计算的金币金额，付款方扣除同样金额，请求方持有的人情扣除原生费用。拒绝结果需要核对金币和人情均保持原值。公开结果提供受控国家自身的前后金币余额，以及兑换涉及的转移量和人情变化。
