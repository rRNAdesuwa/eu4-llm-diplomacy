# 保证独立接口与运行验收

R30 已接通保证独立与撤销保证独立。接口控制法兰西（FRA）作出这两个单方选择，目标国萨伏依（SAV）继续使用原生 AI；游戏界面的玩家国是葡萄牙（POR）。

## AI 可以调用什么

| 动作 | `action_id` | 执行成功后的变化 |
| --- | --- | --- |
| 保证目标国家独立 | `proclaim_guarantee` | 法兰西→目标国的保证关系从不存在变为存在 |
| 撤销对目标国的保证 | `revoke_guarantee` | 法兰西→目标国的保证关系从存在变为不存在 |

两个动作使用 `actor="FRA"`、`phase="initiate"`、`parameters={}`。接受度为 `not_applicable`，目标国无需接受或拒绝。请求军事通行权、支持独立等需要对方回应的动作各有自己的规则和执行路径。

四个统一工具的示例：

```json
{"tool":"list_diplomatic_actions","arguments":{"actor":"FRA","recipient":"SAV","category":"diplomatic_action"}}
{"tool":"inspect_diplomatic_action","arguments":{"action_id":"proclaim_guarantee","actor":"FRA","recipient":"SAV","phase":"initiate","parameters":{}}}
{"tool":"execute_diplomatic_action","arguments":{"request_id":"my_guarantee_001","action_id":"proclaim_guarantee","actor":"FRA","recipient":"SAV","phase":"initiate","parameters":{}}}
{"tool":"get_diplomatic_result","arguments":{"request_id":"my_guarantee_001"}}
```

撤销时把动作换成 `revoke_guarantee`，使用新的唯一请求号。同一请求号重复调用会返回已有结果，不会再次提交。执行前，接口重新调用当前原生规则并核验桥接授权。

查询结果分开回答三个问题：

- `legality.status`：此刻能否执行。游戏的附属关系、已有保证、外交官数量和再次派遣冷却都会影响答案。
- `relationship_state.guarantee_active`：法兰西当前是否保证目标国独立。`complete=true` 表示该关系状态已从原生关系判定取得。
- `resources.diplomats.available_count` 与 `native_diagnostic.text`：可用外交官数量，以及游戏返回的说明或禁止原因。

保证关系会在外交官归来后继续存在。调用方应读取 `relationship_state` 判断保证关系，读取 `legality` 判断当前能否撤销，不能把外交官已经空闲等同于撤销已经可用。

`get_diplomatic_result` 在原生执行及关系变化得到确认后返回 `executed`，并附 `guarantee_before`、`guarantee_after`。请求与会话、双方、动作、日期、阶段和单方变体必须全部匹配。运行时证据缺失时，结果保留等待或未知状态。

## 原生实现依据

保证独立与撤销保证使用 `guaranteeaction`，选择器为 `0x2941`，对象大小为0x40。两种模式均为原生 `state=0`；mode1建立、mode0撤销。原生UI工厂创建对象，通用投递、复制、接收与执行流程处理外交官和关系变化。授权在原生分配外交官之前绑定完整对象；引擎随后填写的外交官编号作为执行后变化记录。

支持独立使用另一类对象和选择器 `0x2f2e`，其接受／拒绝会读取state2／state1。保证接口没有开放支持独立的执行。两类的附属国上下文与方向已有[静态识别](../work/runtime/guarantee-support-identification-20261015-001/report.md)和[集成核对](../work/runtime/guarantee-support-identification-20261015-001/guarantee-integration-20261015-001/report.md)；支持独立的实际操作继续单独实施。
