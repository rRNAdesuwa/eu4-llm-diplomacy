## 四阶段交付计划

1. **能力矩阵和现有路径复核。** 把每类动作拆成动作选择/显示、发起、接受、拒绝、撤销，以及查询、执行、结果、持久化阶段；登记真实动作标识、actor/recipient、决策主体、对象生命周期、ABI、来源、已验证入口和缺口。分别复核原生 UI 动作选择/显示、合法性、参数与条款费用、对方接受意愿、执行时复检，补充正常、规则禁止、查询后状态变化和非法/重复/过期请求用例。不要用一个 `true` 推断全规则，也不要把排队、静态分析、编译或入队当作业务成功。

2. **公共工程和实验基础。** 整理版本/哈希/签名校验、正确游戏帧线程调度、稳定请求编号、请求状态机、授权的创建—复制—传输—反序列化—执行—响应—析构生命周期、结构化日志、错误与超时、实验存档保存字段读取、历史重载证据归档、文件哈希和证据归档。查询与执行都按最新状态复检；每次实验绑定游戏/DLL 哈希、场景、动作、参数、决策国、请求号、状态变化和独立证据文件。

3. **联盟端到端示例。** 先只读定位联盟的动作选择、提议、接受、拒绝、撤销对象和决策国，再实现：完整查询；原生 AI 对受控国的同类权限隔离；桥接授权只决定受控方是否可替其作选择，不能改变游戏合法性；沿正常构造/投递/响应链调用原生执行；证明其他国家仍能按原生 AI 正常响应；最后读取保存字段并核对结果、停战/关系/对象状态，引用已有重载证据。未观察到响应必须保持未知，接受和拒绝要分别取证。

4. **代表性限制、家族扩展和整合。** 独立验证保证/支持独立的上下文切换，验证王室联姻的政体改革例外，验证外交官任务的持续状态、外交官可用性和归途；只有确认对象布局、生命周期、决策主体和规则入口共性后才批量扩展。完成优先清单后再按目录补齐其他动作、议和条款、公平信息、常驻模型和长期循环；不要为未知内部接口预先承诺成功。

## 统一外部接口

对每一类已经识别并进入实施范围的动作，一起实现并在矩阵中登记以下四个语义入口：`list_diplomatic_actions` 返回真实动作标识、中文说明、类别、参数定义、查询/执行支持状态及未知原因；`inspect_diplomatic_action` 返回双方、阶段、可见性、合法性、实际参数/候选项、费用、原生接受信息和证据完整性；`execute_diplomatic_action` 接收唯一请求编号、明确动作和参数，执行最新合法性及授权复检，返回是否提交及后续关联标识；`get_diplomatic_result` 返回实际执行、等待响应、接受、拒绝、撤销、过期、失效及后果。LLM 只接触稳定动作语义和参数，不接触 PID、RVA、DLL 路径、内存地址、请求文件标记或任意控制台代码。

所有查询分开报告接口支持、会话就绪、游戏合法性和桥接授权。合法性使用 `available`、`unavailable`、`unknown`，原因必须有稳定代码、可读文本、来源（原生规则/桥接策略/运行错误）和完整性；原生只给出首个原因或尚未解析的层必须明确标记不完整。接受度独立于合法性：返回是否适用、预测是否可取得、原生接受度总值、已核验的单位/尺度、响应预测、明细是否可取得及每项标识/名称/原生数值/来源/完整性；总值不是擅自换算的概率，不能假定等于明细相加。单方动作用 `not_applicable`；接收方是玩家或 LLM 时不冒充原生 AI 的真实接受预测。议和必须携带完整战争、方向、条款、对象、互斥、费用和参数上下文，不以双方 tag 代替。
