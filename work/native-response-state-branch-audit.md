# `598f00` 响应状态分支审计

范围：只读反汇编 `work/runtime/peace-response-598f00.txt`，没有注入、发送或修改其他文件。本文保留状态编号原义，不把 `+0x34` 的数值命名为接受或拒绝。

## 关键结论

在本版本的 `598f00` 控制流中，`action+0x34 == 1` **没有到达** `0x59a716`，因而没有到达其后的 `call 0x9765a0`。这解释了本轮日志出现 `state_raw:0` 后 `state_raw:1`、但战争仍未结束：至少从这条响应处理函数看，状态 1 分支不会调用和平执行函数。

`0x9765a0` 的调用点是：

```asm
RVA 0x59a716: mov rcx,[rbp-0x38]   ; RCX = action + 0x48
RVA 0x59a71a: call 0x9765a0
```

它只有在此前若干非状态 1 路径落到 `0x59a716/0x59a712` 时才执行。仅凭这条调用不能给状态 1 重新赋予其他语义。

## 状态分派

入口第一次读取状态的位置是 `RVA 0x59951b`：

```asm
mov eax,[r12+0x34]
cmp eax,2
je  0x599bb8
test eax,eax
jne 0x599658
```

因此：

- `+0x34 == 2` 进入 `0x599bb8`；
- `+0x34 == 0` 继续从 `0x599531` 执行；
- 其他值先到 `0x599658`。该块在 `0x599658` 又执行 `cmp eax,1`，`RVA 0x59965b` 的 `jne 0x599adb9` 会把所有既不是 1 的值送到函数尾部；所以这里实际只有 `+0x34 == 1` 能继续状态 1 路径。

## 状态 1 的完整可见路径

状态 1 在 `RVA 0x599658` 先检查：

```asm
mov rax,[r12+0x18]
shr rax,0x20
cmp ax,r15w
jne 0x599893
```

`r15w` 是函数前部从当前玩家句柄取得的国家槽位；`action+0x18` 是构造函数把第一个国家句柄复制进去的位置（构造函数 `0x598b20` 的 `0x598b38`）。这只是原始槽位比较，本文不把它解释成接受方或拒绝方判断。

### 槽位相等：`0x599674`

相等时执行 `0x599674` 起的通知/辅助路径，随后在 `0x59988e` 无条件跳到 `0x599a7d`。该路径不跳到 `0x59a716`。

### 槽位不等：`0x599893`

不等时先执行：

```asm
RVA 0x599893: mov rdx,rdi
RVA 0x599896: mov rcx,[r14]          ; action+0x20 的句柄
RVA 0x599899: call 0x0985b0
RVA 0x59989e: test al,al
RVA 0x5998a0: je  0x599967
```

若该调用返回非零，路径经 `0x5998a6` 的辅助/通知处理在 `0x599962` 跳到 `0x599a7d`；若返回零，则进入 `0x599967`。`0x599967` 依据当前国家对象的 `+0x959` 位、句柄高位字节和 `+0x5d8` 的辅助调用 `0x0c62e0` 继续分支：`0x5999c2` 在该辅助调用返回零时跳到 `0x599a8a`，否则先走一段消息构造后也汇合到 `0x599a7d`，再落到 `0x599a8a`。

共同尾部 `0x599a8a` 的条件是：

```asm
RVA 0x599a8a: call 0x983e90
RVA 0x599a95: je  0x599adb9
RVA 0x599a9e: call 0x2896a0
RVA 0x599aa5: jne 0x599adb9
RVA 0x599ad9: cmp dword ptr [country+0xbd8],-3000
RVA 0x599adf: jne 0x599b59
```

`0x599b59` 和 `0x599adb9` 都最终离开该响应函数；在这条状态 1 路径上没有通往 `0x59a716` 的边。整个状态 1 可达子图的静态目标检查也未发现 `0x59a716` 或 `0x59a712`。

## 方向和 preview 字段

在 `598f00` 内，状态 1 可达路径没有读取 `action+0x41`（方向），也没有读取 `action+0x208`（当前探针称为 `preview_flag`）。对这两个字段的读取位置只有：

- `RVA 0x599579`：状态 0 路径要求 `byte [action+0x41] != 0`，否则跳到 `0x59adb9`；
- `RVA 0x599bc0–0x599bdc`：状态 2 路径依据 `action+0x41` 在 `action+0x10` 与 `action+0x20` 两个句柄之间选择顺序；
- `action+0x208` 在本函数反汇编中没有读取指令。

所以本函数的静态证据不能把本轮 `direction=1` 或 `preview_flag=0` 说成状态 1 的跳过原因：状态 1 本身不依赖它们。若 `preview_flag` 影响响应，它发生在进入 `598f00` 之前或另一条虚表/调用路径。

## `9765a0` 的可见前置

`0x9765a0` 只有一个直接调用点 `0x59a71a`。到达该点的局部前驱是 `0x59a716`，其前面可见的汇合边来自：

- `0x599f8d -> 0x59a716`；
- `0x59a108 -> 0x59a716`；
- `0x59a453 -> 0x59a716`；
- `0x59a5ac -> 0x59a716`；
- `0x59a710 -> 0x59a716`，以及 `0x59a1ef` 条件成立时先到 `0x59a712` 再落入 `0x59a716`。

这些汇合块属于状态 0/2 后续处理，或从状态 0/2 共享的合法性分支；状态 1 的 `0x599658` 子图不包含它们。各个外部辅助函数的业务语义尚未在本窄审计中命名，因此报告只记录原始返回条件。

## 证据边界

- 本报告证明的是 `598f00` 的静态控制流，不证明 `0x9765a0` 一定成功结算，也不解释 `state_raw` 数值语义。
- 当前用户反馈的“战争未结束”与状态 1 不到 `0x9765a0` 相符，但仍需对会实际落入 `0x59a716` 的另一状态或调用路径做独立验证。
