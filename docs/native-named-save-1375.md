# 1.37.5 原生命名保存的静态调用链

已经找到保存界面真正使用的文件名入口：`0x1175110 → 0x5cbee0 → 0x5cbde0 → 0x5c6500`。**尚未实现或调用保存适配器**。本机这条链可以删除临时文件、备份或替换目标文件，不能直接提供 `CREATE_NEW` 保证；原生返回 0 也不能单独证明最终存档已产生。

证据固定于 EXE SHA256 `9AD3EFE1AF169F40EE577F9DAE5DEBBC87AF6FB8B5450FB345EBF110DC4D771A`。生成器 [trace_named_save.py](../work/trace_named_save.py) 和报告 [native-named-save-1375.json](../work/reports/native-named-save-1375.json) 只读取磁盘 PE，包含 26 个有界入口、25,441 字节代码和 9 组逐指令事实。报告 SHA256：`e22b3eb793bb0bd95b22347dd7284b4ea06ddc9e4c3d7de4de7c3dd1225cb6c0`。所有运行与执行验证字段均为 false。

## 从名称输入到保存请求

`1175110` 从 GUI `game_name` 输入框读取 String32，复制、处理文本并拒绝空名称；`1174840` 为输入框配置了 `\ / : * ? < > |` 等禁止字符。`1705180 / 17043c0` 的完整规范化语义未命名，不将它们当成充分路径校验。未来测试只能接受宿主生成的 `llm_test_` 加 ASCII 小写字母、数字、下划线，不能开放路径、扩展名、目录 vector 或任意脚本输入。

本地分支用 `5ca070` 组装路径，`19f6ea0` 检查同名文件。存在时构造 `11bd6e0` 确认对话框，引用 `CONFIRMSAVETITLE / CONFIRMSAVETEXT`；未存在的分支调用 `5cbee0`。绕过 UI 调用底层函数，也会绕过这一步提示。

按 MS x64 机器约定，`5cbee0` 的参数为：

| 位置 | 含义与证据限度 |
|---|---|
| RCX | 可移动、拥有存储的原生 String32 名称 |
| DL | 复制到保存请求 `+0x22`，来自压缩选项 |
| R8B | `+0x23`，UI 根据服务器状态计算，完整语义尚未命名 |
| R9B | `+0x24`，本地现有目标的备份分支开关 |
| 入口 RSP+0x28 | `+0x25`，旧文件轮转分支开关 |
| 入口 RSP+0x30 | 只读 Vector24&lt;String32&gt; 目录组件指针 |

函数复制模板 `1fd2e70`，将传入名称的 32 字节 **move** 到局部请求，再把传入对象重置为空 SSO；正常退出还会处理该输入的析构。不能把普通宿主堆字符串伪装成原生拥有存储的 String32。`5cbde0` 使用这个借用请求作同步分派；`5cbee0` 返回前还可能关闭或更新保存 UI，所以它不是纯粹的文件写入原语。

请求布局为名称 String32 `+0`、7 个 BYTE 标志 `+0x20..0x26`、目录 vector `+0x28..0x3f`、错误提示标志 `+0x40`；自然对齐大小推断为 `0x48`，未做原生 ABI 运行验收。磁盘模板的 7 字节为 `00 00 01 01 01 00 01`，`+0x40=1`。运行时模板是否被更改仍须核对。

`5cbde0` 在标志 `+0x20=0 / +0x21=0` 时调用普通本地 writer `5c6500`；其他组合会进入 Ironman 候选分支或 cloud 分支。本轮只分析普通本地保存路径，不能据模板初值承诺任何当前世界都会走它。

## 目录、文件名和覆盖

CRT 初始化器 `7eb10` 将字面量 `save games` 写入 String32 全局 `1fd2f28`。`5c9c00` 还读取配置指针 `[242bde8]+0xe0` 的可选前缀，并加入目录 vector 的组件。`5ca070` 在其后附加 `/`、名称和 `.eu4`；`5ca280` 剥离已有 `.eu4 / .tmp` 后生成临时 `.tmp` 名称。

这些首先是虚拟文件系统路径。实际用户目录、模组前缀、挂载根、重解析点和物理输出位置不能从固定字符串推定；受限适配器必须独立比对实时解析结果与获准测试目录。本轮没有读取游戏内存来完成这项绑定。

`5c6500` 的行为包括：

1. 临时 `.tmp` 已存在时记录删除提示并调用 `17165b0`，随后通过 `1718300(mode=1, buffer=0x20000)` 打开。
2. 完成序列化后关闭输出，做大小与格式检查。
3. 最终 `.eu4` 已存在时可能进入备份、`old_` 轮转或删除分支。
4. 通过 `1715bb0 → 1a5ed40` 重命名临时文件。

`1a5ed40` 调用导入的 `MoveFileExW`，参数为 `flags=2`；这是 `MOVEFILE_COPY_ALLOWED`，没有 `REPLACE_EXISTING` 或 `WRITE_THROUGH`。但保存函数在它之前已有删除／轮转分支，不能把最终 rename 的参数当成整条保存链的无覆盖保证。[Microsoft 的参数定义](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-movefileexw)

因此，**不能先在最终 `.eu4` 创建占位文件，再调用该保存链**。原生代码可能把这个占位文件视为应备份或删除的旧存档。独占 `CREATE_NEW` 应先用于独立、永久保留的 attempt claim；它只能阻止研究端重复请求，不锁住 native writer 的文件路径。仅检查文件不存在还有 TOCTOU 窗口，仍不足以宣称原子新建。

## 同步边界与成功判据

`5c6500 → 74ba20 → 5cde60` 可启动一个 TBB 辅助线程；主序列化／压缩体 `5ce5f0` 在当前调用上同步运行，`5cde60` 退出前会 `join` 辅助线程。这不是已发现的独立异步保存接口。研究宿主要为游戏线程中的长耗时调用设计时间边界，不能套用普通短帧请求的完成时间假设。

之后 `5c6500` 调用 `19f66c0` 关闭流、释放包装对象，执行文件检查和 rename。然而关闭返回值未用于最终结果；尤其 rename 失败时，错误日志分支会回到公共退出，而成功序列化时设置的 `R12D=0` 没有改写。`5cbee0` 仍可能返回 0。

未来验收必须分别保留：提交前独占 claim 与所有候选文件缺失证据；原生进入／正常返回／异常与所有权结果；最终文件的新身份、完整可解析内容、日期／玩家／目标关系、哈希及临时文件状态；新进程重载后的效果。函数返回、TBB join 和正常 rename 都不是持久化介质或重载成功的替代证据。

## 下一步限制

在编写任何可调用模块前，仍须完成实时 VFS／目录绑定、完整标志解释、受限隔离命名空间策略和异常所有权审查。只能使用获准测试目录下宿主生成的新名称，拒绝 `.eu4 / .tmp / backup / old_` 等所有候选碰撞和重解析路径。不能通过扫描未知数组、修改 writer 开启参数或放宽任意路径来绕过这些缺口。

本报告没有保存游戏、创建存档、注入 DLL 或改动 v6 源码／产物，也没有新增对外执行能力。

```powershell
python -B work/trace_named_save.py --deps-dir "$env:TEMP/eu4-native-analysis-deps"
python -B work/trace_named_save.py --deps-dir "$env:TEMP/eu4-native-analysis-deps" --check
```

每个入口上限 16 KiB／4,000 指令，合计代码上限 256 KiB，内存守卫 768 MiB；不递归追踪调用。导入表只静态解析，并独立钉扎 `MoveFileExW` 和 TBB start/join 名称。
