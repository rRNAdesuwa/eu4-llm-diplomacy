# 宣战接口与运行验收

更新：2026-10-16。

统一接口已经完成一次真实宣战执行。法兰西（FRA）以 `cb_core`、目标省份 177、受益国 FRA、空参战盟友列表向英格兰（ENG）宣战；原生事件记录 `war_before=false` 到 `war_after=true`，结果为 `executed`。执行后原始报告曾因桥接层重复解析回执而错误写成 `invalidated`，修复后使用同一个请求只读回收，journal 重开后仍返回 `executed`，新进程载入存档后战争继续存在。保存文件对照还确认了新的 FRA→ENG 战争、`cb_core` 和省份 177。公开战争标识和执行事件中的即时稳定度数值当前为 `null`，对应验证状态为 `false`；保存对照中的稳定度结果独立列出。

## 谁在查询，游戏处于什么状态

玩家国家是葡萄牙（POR），接口查询的行动国是法兰西（FRA）。普罗旺斯的国家标签是 PRO，与葡萄牙不同。实验从取消伦斯特附庸后的独立命名存档启动，暂停在 1454.12.1。查询期间没有切换玩家国家或推进日期。

## R37B：FRA→ENG 的真实宣战执行

本次请求使用统一执行入口，参数如下：

```python
selection = {
    "casus_belli": "cb_core",
    "war_goal": {"province_id": 177, "beneficiary": "FRA"},
    "call_allies": [],
}

api.execute_diplomatic_action(
    "r37b_declare_eng_core177_001",
    "declare_war", "FRA", "ENG", "initiate", selection,
)
```

执行发生在 raw date `56545056`（存档日期 `1454.12.1`）。桥接层先用同一组 CB、省份、受益国和会话日期核对查询结果，再提交一次 `EXEC3` 请求。原生提交回执包含 `submitted=true`、`transport_verified=true` 和 `request_binding_verified=true`。原生执行结果包含 `outcome=executed`、`execution_verified=true`、`request_binding_verified=true`，并明确记录战争从不存在变为存在：

| 结果字段 | 实际值 | 含义 |
| --- | --- | --- |
| `war_before` / `war_after` | `false` → `true` | FRA 与 ENG 的战争关系实际建立 |
| `casus_belli` | `cb_core` | 执行事件与请求参数一致 |
| `war_goal_province` | `177` | 执行事件与请求参数一致 |
| `war_goal_beneficiary` | `FRA` | 执行事件与请求参数一致 |
| `war_id` | `null`，`war_identity_verified=false` | 已读取进程内战争对象引用，公开战争标识的映射继续开发 |
| `stability_before_raw` / `stability_after_raw` | `null`，`stability_verified=false` | 本次执行事件没有提供可验证的原生稳定度数值 |

结果接口分别返回战争是否建立、公开战争标识是否已取得，以及即时稳定度是否已读取。AI 可以根据 `executed` 和交战状态继续决策，并根据验证状态判断哪些辅助数值可用。

### 授权负例与回执消费修复

同一游戏日期还验证了两个授权入口。`direct_entry` 和 `transport` 都向原生发送了合法形状的 FRA→ENG 宣战对象，但两次均收到 `UNAUTHORIZED_FRA_DECLARE_WAR`，战争双方、日期和外交官状态保持不变。transport 负例的完整分发检查通过；direct 负例的原始报告因 `native_authority_dispatch_complete=false` 被标记为 `failed`，但该报告同时记录了 `native_expected_rejection=true`。这两个结果说明授权门确实拦截了未授权入口，direct 验证器的附加假设不能代替原生拒绝事件。两份原始负例报告均保留。

对应证据为 [direct_entry 负例](../work/runtime/diplomacy-query-20261016-r37-war-b-execution/declare-war-authority-test-2389ddcc1510439da7689dad873a3347/report.json) 和 [transport 负例](../work/runtime/diplomacy-query-20261016-r37-war-b-execution/declare-war-authority-test-db15852e5a49408e90914c3cc3baa5c0/report.json)。

真实业务请求最初出现了另一类消费端错误：原生提交回执已经在 `submit_declare_war` 中压缩为公共回执，执行层又把这份公共回执当作原始事件再次解析，导致 `NATIVE_DECLARE_WAR_SUBMISSION_RECEIPT_INVALID`，原始业务报告因此保留为 `invalidated/submitted=false`。修复后，执行层直接校验已压缩回执；只读 resume 重新读取同一 request、receipt 和 execution event，未发布新请求，journal 关闭重开后仍为 `executed/submitted=true`。

### 保存与新进程重载

流式 save pair 以执行前存档 `6adfdce8dd608eb65b054dada26804dac0f184f07a14428e6eef9b15d0f4b0d9` 和执行后存档 `083fd5fc0e98312fdc810c7dbd93be54b538ba17a1aca57bd3ed0fab2f7b00f2` 对照。执行后存档新增一条当前 FRA→ENG 战争，原始攻击方为 FRA、原始防守方为 ENG，`take_core.casus_belli="cb_core"`、`take_core.province=177`。FRA 的 `stability` 为 `1.000 → 1.000`，`prestige` 为 `-21.933 → -21.933`，保存解析没有发现这次宣战改变这两项数值。

随后新进程读取同一保存文件。重载 reconciliation 的 19 项检查全部通过：日期、POR 玩家槽位、暂停状态、存档哈希、DLL 哈希、FRA→ENG 双向战争状态、请求参数和 journal 中的 `executed` 结果均保持一致。原始重载报告因比较器读取了不存在的 `loaded_dll_sha256` 字段而保留 `failed`；独立 reconciliation 报告修正了比较字段，没有重写原报告，也没有执行或保存新业务。

## R36E：选择参数后查询合法性和费用

AI 通过统一接口选择宣战方案：

```python
inspect_diplomatic_action(
    "declare_war", "FRA", "ENG", phase="initiate",
    parameters={
        "casus_belli": "cb_core",
        "war_goal": {"province_id": 177, "beneficiary": "FRA"},
        "call_allies": [],
    },
)
```

接口在当前游戏中重新枚举候选，按参数唯一匹配，再用游戏自己的复制函数把选中对象交给临时宣战动作。查询完成后释放临时对象。AI 使用 CB 键、游戏省份编号和国家标签，不依赖候选的临时排列顺序。

| 查询方案 | 原生选择与条件 | 统一接口结果 | 原生费用预览 |
| --- | --- | --- | --- |
| 收复核心，省份 177，受益国法兰西 | 唯一匹配；原生条件通过 | `available`，参数上下文完整 | 稳定度损失 0，WAREX 和主显示量为 0 |
| 收复核心，省份 2147483647 | 当前候选没有该省份 | `unavailable` | 省略默认对象费用 |
| 显式无 CB，省份 -1 | 原生空战争目标对象；条件通过 | `available` | 损失 2 稳定度、增加 2 厌战度；原生文字预计 171 个国家受到 0～17 点侵略扩张关系惩罚 |
| 空参数 `{}` | 枚举候选并读取默认对象 | `unknown`，等待选择方案 | 标注为未选参数的默认无 CB 预览 |

费用整体为 `partial`。稳定度条目提供原始值、1000 缩放单位和明确数值；其他显示量保留原始值及游戏中文说明。实际扣费将在执行阶段核对。

首次运行的四个原生查询均完成，消费端却把候选全集误当成“每一行都必须等于选中参数”，拒收了三条参数回执。修正后先回放原有事件，再直接查询一次有效省份和一次不存在的省份，两项均通过。[实际统一接口验证](../work/runtime/diplomacy-query-20261016-r36-war-e-selected-context/live-api-selected-query-0840c41dca4849df9af54db6620914b5/report.json)、[原四查询与前后状态](../work/runtime/diplomacy-query-20261016-r36-war-e-selected-context/declare-war-parameter-queries-d3482330d770494bb3c8f8850bb1e1bd/report.json)及[只读回放](../work/runtime/r36-war-e-selected-context-readback-20261016-001/report.json)分别保留。
