### 查询结果怎样表示

| 字段 | 含义 |
| --- | --- |
| `family`、`action_id`、`actor`、`recipient`、`phase` | 说明本次查询属于 Rival family、查询哪项动作、由哪国对哪国发起，以及查询阶段 |
| `session.status`、`session.date_raw` | 说明查询来自哪个已就绪会话和哪个游戏日期；公共日期以 `session.date_raw` 为准 |
| `relationship_state.rival_active` | 表示 FRA 与目标国家当前是否存在宿敌成员关系；`rival_since_date_raw` 给出列表中的原生起始日期 |
| `rival_count`、`max_rivals` | 表示 FRA 当前宿敌数量和原生上限 |
| `native_command_validity`、`native_command_validity_called` | 表示游戏原生 Set/Remove 条件函数是否被调用，以及该函数返回值 |
| `diplomatic_power_raw`、`at_war` | 表示原生条件检查读取到的外交点原始值和战争状态 |
| `acceptance` | 宿敌不需要接收国同意，因此 `applicability=not_applicable` |
| `candidate_eligibility_available`、`full_rules_complete` | 说明候选列表和完整 UI 规则的恢复范围；R34A 两项均为 `false` |

本次 FRA 的 `rival_count=3`、`max_rivals=3`、`diplomatic_power_raw=162`、`at_war=true`。六条查询的原生动作条件均返回 false，公共 `legality.status` 为 `unavailable`；成员关系仍由 `relationship_state.rival_active` 独立表示。例如 BUR 和 ENG 的成员状态为 true，同时 `remove_rival` 的当前条件仍为 false。这样可以区分“目标已经是宿敌”和“此刻游戏允许执行移除动作”两个问题。Remove 事件的原生诊断已由 `eu4_escape` 解码为“不能在战争期间移除宿敌”，公开 `queries.json` 的 `native_diagnostic.text` 保存该可读原因。

### 人类和 AI 怎样调用

统一 Python 接口可以直接查询一项动作：

```python
api.inspect_diplomatic_action(
    "set_rival", "FRA", "BUR", phase="initiate", parameters={}
)
api.inspect_diplomatic_action(
    "remove_rival", "FRA", "BUR", phase="initiate", parameters={}
)
```

批量运行 R34A 的只读操作器时，可以重复 `--recipient`，并用 `--expected-rival` 声明成员状态预期：

```powershell
python work/run_rival_queries.py `
  --installation work/runtime/diplomacy-query-20261016-r34-rival-a/installation.json `
  --expected-date-raw 56465136 `
  --recipient BUR --recipient ENG --recipient HAB `
  --expected-rival BUR=active `
  --expected-rival ENG=active `
  --expected-rival HAB=absent
```

操作器在查询前保存四份边界快照，随后为每个目标查询 `set_rival` 和 `remove_rival`，最后复制与 session、action、recipient 和 raw 日期对应的 native event slice。操作器不会调用执行接口、推进日期、保存游戏或安装 DLL。

## AI 能读到哪些接受度因素

法兰西向萨伏依查询结盟时，接口实际返回以下六项。标识来自原生本地化键；中文名称来自游戏输出的文本。

| 因素 | 稳定标识 | 原生数值 |
| --- | --- | ---: |
| 法兰西与萨伏依的敌人普罗旺斯结盟 | `DIPLO_ENEMY_ALLIES` | −25 |
| 法兰西陆军实力 | `DIPLO_ARMY_SIZE` | +20 |
| 法兰西海军实力 | `DIPLO_NAVY_SIZE` | +7 |
| 萨伏依对法兰西的好感度 | `DIPLO_OPINION` | +4 |
| 萨伏依对法兰西的态度为友好 | `DIPLO_ATTITUDE` | +50 |
| 法兰西的外交声誉 | `DIPLO_DIPLOMATIC_REP` | +8 |

引擎返回总值 `64`、`native_would_accept=true`，接口预测为 `accept`。立陶宛的因素为陆军 +2、海军 +7、好感度 +6、中立态度 −20、外交声誉 +8，以及 `DIPLO_BORDER_DISTANCE` 边界距离 −29；总值为 `−26`，接口预测为 `reject`。

王室联姻有自己的接受因素。r25d 中，萨伏依的因素为好感度 +4、友好态度 +40、同为天主教 +5、邻国 +5、法兰西外交声誉 +8；原生总值为 62，当前愿意接受。立陶宛的总值为 −30，当前不愿接受。五项稳定原生标识均已验证；构造 caller、原生 key 与实际数值的绑定沿用 [r25c 因素来源映射](../work/runtime/diplomacy-query-20261015-r25-royal-c/royal-marriage-queries-2ed042ec7dd444d9a8f219b8008b3278/reason-metadata-mapping-001/report.md)。这些是原生查询预测，实际提议后的选择将登记在执行结果中。

每项均已在运行中核对最终原因行、文本及数值，Royal 五项返回 `identifier_verified=true` 和 `native_value_verified=true`。数值保留游戏的有符号 32 位整数；业务单位仍按原生整数保存，接口提供 `unit="unknown"`。AI 根据 `native_would_accept` 使用当前意愿判断，实际回应通过结果工具取得。

## 合法性与接受度怎样导出

原生模块调用游戏自己的动作选择、按钮条件、联盟合法性和接受度检查，再复制结果；Python 桥接程序解码文本并输出 JSON。当前实现文件为[原生查询](../work/native/alliance-query.inc)、[因素来源捕获](../work/native/alliance-reason-metadata.inc)和[统一接口](../bridge/diplomacy.py)。

`legality.status` 回答游戏规则是否允许操作，取值为 `available`、`unavailable` 或 `unknown`；`acceptance` 回答接收国当前的接受意愿。例如立陶宛查询返回合法性 `available`，接受预测为 `reject`。费用、具体禁止条件的详细解释、所有可能因素和中文编码的独立验证继续登记在各自完整性字段中。

法兰西收到外来提议时，接受或拒绝由 LLM 选择。接口复查提议仍在队列、法兰西是决策方和原生响应合法性，再沿原生响应链提交选择。断盟属于单方动作，接受信息为 `not_applicable`。

r24 的断盟执行报告中 10 项检查全部通过：请求已提交，原生结果为 `executed`，联盟状态从存在变为不存在，重复请求返回已有执行结果，日志关闭重开后仍能关联。来源验证核对了请求在原生传输、读取、复制和执行入口中的对象与参数，48 项检查通过。执行后的外交官可用数从 1 变为 0；[归途观察](../work/runtime/alliance-query-20261015-r24b-authority/lifecycle-observation-61d86dff7ec04da09f704524a91cca2b/dissolve-envoy-validation-001.json)记录外交官后来恢复空闲，另三名外交官的任务保持相同。

授权对照实验把合法原生命令送进相同投递流程，省略桥接授权。结盟与断盟均在执行入口被拦截，两份独立来源报告各有 63 项检查通过。这些实验检验普通命令的授权门；原生 AI 自发作出外交选择的覆盖情况继续按具体入口登记。

## 四个工具怎样调用

外部入口 [tools/diplomacy.py](../tools/diplomacy.py) 按行接收 JSON，每行返回一个 JSON 结果。

| 工具 | 输入 | 输出 |
| --- | --- | --- |
| `list_diplomatic_actions` | 可选国家和类别 | 动作、中文说明、参数、查询与执行支持状态；法兰西的已观察入站提议 |
| `inspect_diplomatic_action` | 动作、发起国、接收国、阶段、参数 | 会话状态、动作显示、原生合法性、接受因素、资源和桥接授权 |
| `execute_diplomatic_action` | 唯一请求编号和上述动作参数 | 最新规则及授权复查、是否提交、关联结果 |
| `get_diplomatic_result` | 请求编号 | 等待、接受、拒绝、失效等状态及实际后果 |

目录登记 39 项：19 项常用外交操作、19 项常用议和条款和单独列出的支持独立。每项的支持字段说明当前实现状态。

查询法兰西向萨伏依结盟：

```json
{"tool":"inspect_diplomatic_action","arguments":{"action_id":"offer_alliance","actor":"FRA","recipient":"SAV","phase":"initiate","parameters":{}}}
```

取得法兰西收到的提议：

```json
{"tool":"list_diplomatic_actions","arguments":{"recipient":"FRA"}}
```

从返回的 `incoming_proposals` 复制 `proposal_id`，先查询拟作出的响应，再提交相同选择。下面以接受萨伏依提议为例：

```json
{"tool":"inspect_diplomatic_action","arguments":{"action_id":"offer_alliance","actor":"SAV","recipient":"FRA","phase":"accept","parameters":{"proposal_id":"从目录返回值复制"}}}
{"tool":"execute_diplomatic_action","arguments":{"request_id":"inbound_accept_001","action_id":"offer_alliance","actor":"SAV","recipient":"FRA","phase":"accept","parameters":{"proposal_id":"从目录返回值复制"}}}
{"tool":"get_diplomatic_result","arguments":{"request_id":"inbound_accept_001"}}
```

拒绝使用 `phase="reject"` 和另一唯一请求编号。实际接受结果包含 `status="accepted"`、`native_state=2`、`alliance_after=true`、`pending_removed=true`；拒绝结果包含 `status="rejected"`、`native_state=1`、`alliance_after=false`、`pending_removed=true`。两种结果均已关闭并重开 SQLite 核对。

运行人员通过 `--operator-session` 绑定当前安装记录。AI 的请求只包含动作语义、国家、公开提议编号及参数。路径和本机配置见[路径配置](路径配置.md)。

## 运行人员怎样复现实验

在独立原始实验存档中构建并安装带因素捕获的模块。每个游戏进程只安装一次；新实验使用新的目录和请求编号。

```powershell
./work/native/build-diplomacy-observer.ps1 -Experiment <新实验名称> -ReasonMetadata
./work/native/restart-game.ps1 -SavedTestGame -SaveName llm_diplomacy_observer_returned_20261013_r3.eu4
python tools/start_diplomacy_observer.py --pid <新PID> --manifest work/runtime/<新实验名称>/build-manifest.json --confirm-load-warning --native-text-codec eu4_escape --wait-ready 120
python work/run_alliance_reason_metadata.py --installation work/runtime/<新实验名称>/installation.json
python work/run_alliance_inbound_response.py --installation work/runtime/<新实验名称>/installation.json --decision accept --request-id <唯一编号> --generate-test-proposal
```

最后一条命令仅在实验中生成萨伏依原生结盟提议，法兰西的响应由四个统一工具执行。接受与拒绝使用各自独立载入的场景。安装完成后等战役和帧心跳就绪，再执行运行脚本。

保存使用 [save_observer_experiment.py](../tools/save_observer_experiment.py)，`--expected-date` 接收 `1445.3.12` 这类存档日期。重载使用 [validate_alliance_reload.py](../work/validate_alliance_reload.py)，通过 `--sav-outcome accepted` 或 `rejected` 指定当前场景的预期联盟关系。当前已验收命名存档包括 `llm_diplomacy_inbound_accepted_20261014_r23b.eu4`、`llm_diplomacy_inbound_rejected_20261014_r23c.eu4` 和 `llm_diplomacy_dissolved_pro_20261015_r24.eu4`。r24 存档 SHA-256 为 `7dd89542fe1a89d98a33e27249b13f2d356541afc368b0dcd10ce89d3a81f9ed`；重载报告核对了文件哈希、日期、POR、暂停状态和 PRO 联盟不存在。

新构建的 `llm_diplomacy_alliance_results_20261015_r24d.eu4` 已通过[重载核对](../work/runtime/alliance-query-20261015-r24e-results-reload/reload-validation-c4fedb28997f4247aeb2bc526df0eeff/report.json)：萨伏依联盟存在、立陶宛联盟不存在，外交官任务和归途记录与保存前一致。保存脚本现在只备份和恢复三份轮换自动存档，对其他命名存档记录文件大小与时间；新结果文件仍采用排他创建和内容哈希核对。
