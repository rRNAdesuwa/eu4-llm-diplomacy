# R42：议和条款进入授权记录，两个执行入口已实测拦截

更新：2026-10-16。当前版本为 R42E。接口已将参战国、全部候选条款、选中条款及动作标志纳入同一套字段比较；白和平、10 金币和曼恩省份三种提议，分别通过通用执行入口与和平处理器入口的无授权拦截测试。六次测试各通过 20 项检查，测试前后战争、外交官、玩家和暂停日期一致。

本阶段交付的是议和执行所需的构造、载荷比较、授权记录和入口守卫。公开的 `execute_diplomatic_action` 还没有连接议和发送适配器。下一阶段需要完成正常接收后的调度、法国接收提议的保留与明确回应，再进行真实发送、英国响应、条款后果和保存重载。

## 程序现在保存和比较什么

一份完整的议和字段模型占 110,656 字节。它包括付款国、索取国、方向、四组参与国，以及最多 512 个候选条款的序列化字段和选中索引。当前法国对英国的战争实际生成 87 个候选条款，来自 19 种原生类型。程序还分别比较外层动作的三个标志，防止一份条款相同的提议被改换执行方式。

新 `PeacePayloadRef` 把完整字段存放在观察器自己的堆中，每条生命周期、协议和授权记录只增加一个 8 字节引用。快照封存后，后续记录共享它；两个独立副本仍按字段值比较。原生对象被销毁后，记录中的字段继续有效。出队的环形数组槽位现在使用 C++ 赋值释放引用，避免已消费事件继续保留大快照。

授权账本新增 Peace 家族，现阶段只开放内部的发起状态。账本核对双方、方向、条款和动作标志；空快照、未封存快照、错误付款方以及被修改的条款都会被拒绝。账本的 369 项纯 C++ 检查通过，其中新增了 Peace 从创建记录、序列化、接收、复制到消费凭据的完整测试。

## 正常传输实际走到哪里

[R42E 传输测试](../../work/runtime/diplomacy-query-20261016-r42-peace-e-clone-and-handler-tests/peace-authority-test-9f6424fc0514451ea9b75ad4cd02a321/report.json)已证明原生包装、序列化、读取和接收方包装器复制均发生。传输记录中的双方头字段和全部逻辑字段相等；接收方复制事件来自已验证的原生接收调用点，源和目标都含完整的 87 个候选及选中索引。

该包在 15 秒观察期内没有进入通用执行入口或和平处理器，因此原报告保留 `failed`，没有补发请求。下一步需要定位接收方复制完成之后，原生调度器将命令交给执行入口的具体条件。当前证据没有确认该包被接受、拒绝或丢弃，也没有证明必须推进日期。原生通用外交条件为 false 是一个已导出的事实，其与本次后续调度的关系仍需直接证据。

B、D 阶段曾因日志家族清单遗漏 Peace，未输出协议层复制事件；生命周期中 `4e858d` 的调用记录证明复制实际已经发生。E 修正过滤后直接取得了协议复制事件。这项修复纠正了观察范围，未改变原报告中的失败结果。

## 接受度、请求参数和当前运行

静态调用链已区分两种评分调用：AI 的布尔判断通过 `+b8` 调用模式 0；公开因素查询使用模式 1，取得稳定因素名称。模式 0 还会读取外层预览标志，并可能直接返回 1000。因此，公开因素总值继续作为预览值返回，实际 AI 判断需要独立调用和运行对照。

新增 `bridge/peace_execution.py` 和 `peace-execution-wire.h` 已定义白和平、金钱、省份及金钱加省份的请求参数。金额使用精确十分位检查，省份编号保留顺序，付款国和索取国必须明确指定。当前统一发送适配器尚未消费这些新结构。Python 全套 320 项测试通过，快照引用 19 项检查和独立 wire 解析测试通过。
