# 路径配置

仓库中的公开文档和脚本不包含任何开发者的个人绝对路径；所以克隆仓库后还需要在根据本机路径完善配置文件。

## 1. 创建本地配置

在项目根目录执行：

```powershell
Copy-Item .\local.env.example .\local.env
```

然后编辑 `local.env`，将示例值替换为本机路径。`local.env` 已被 `.gitignore` 忽略，不能提交到 Git，也不能放入发布包。

配置文件采用简单的 `名称=值` 格式，每行配置一个变量。路径中包含空格或中文时可以直接填写；不要把个人路径写回 Python、PowerShell 或 Markdown 文件。

## 2. 配置项

| 配置项 | 必需 | 用途 |
| --- | --- | --- |
| `EU4_GAME_ROOT` | 是 | EU4 安装目录，目录中应包含 `eu4.exe`。安装器、静态检查器、原生探针和实验重启脚本会使用它。 |
| `EU4_USER_DATA` | 是 | EU4 用户数据目录，目录中通常包含 `mod`、`dlc_load.json`、`logs` 和 `save games`。模组安装和实验脚本会使用它。 |
| `EU4_PYTHON` | 是 | 项目要求的 Python 可执行文件。PowerShell 启动脚本使用它运行探针和 DLL 加载器。 |
| `EU4_CXX` | 编译 DLL 时需要 | 原生 DLL 的 C++ 编译器，例如 MinGW-w64 的 `g++.exe`。 |
| `EU4_OBJDUMP` | 离线反汇编时需要 | 用于静态分析游戏二进制的 `objdump.exe`。 |
| `EU4_CRASH_DUMP` | 可选 | `work/analyze_native_crash.py` 默认读取的 minidump；也可以在命令行用 `--source` 单独指定。 |

公开文档中的对应关系如下：

```text
游戏：通过 EU4_GAME_ROOT 指定
用户数据：通过 EU4_USER_DATA 指定
Python：使用 EU4_PYTHON 指定的项目环境
编译器：通过 EU4_CXX 指定
反汇编工具：通过 EU4_OBJDUMP 指定
```

## 3. 配置示例

下面是格式示例，不是可直接使用的真实路径：

```dotenv
EU4_GAME_ROOT=C:\path\to\Europa Universalis IV
EU4_USER_DATA=C:\path\to\Paradox Interactive\Europa Universalis IV
EU4_PYTHON=C:\path\to\python.exe
EU4_CXX=C:\path\to\g++.exe
EU4_OBJDUMP=C:\path\to\objdump.exe
# EU4_CRASH_DUMP=C:\path\to\minidump.dmp
```

项目脚本会自动读取项目根目录的 `local.env`。其中，Python 脚本通过 `work/local_config.py` 读取；PowerShell 脚本通过 `work/native/import-local-env.ps1` 读取。通常不需要手动设置全局环境变量。

## 4. 配置后验证

先运行 Python 语法检查和桥接测试：

```powershell
python -B -m compileall -q bridge work tools
python -m unittest discover -s bridge\tests -v
```

再运行不启动游戏的静态模组检查：

```powershell
python -B .\work\check_mod.py
```

如果静态检查提示缺少 `EU4_GAME_ROOT`，请确认 `local.env` 位于项目根目录，而不是 `work` 或 `work\native` 目录。若提示游戏文件不匹配，请确认 `EU4_GAME_ROOT` 指向目标 EU4 版本，而不是其他安装或启动器目录。

PowerShell 脚本会在运行时检查配置。例如，原生构建脚本读取 `EU4_CXX`，实验启动脚本读取 `EU4_GAME_ROOT`、`EU4_USER_DATA` 和 `EU4_PYTHON`；缺少配置时应停止并提示复制 `local.env.example`。

## 5. 协作和发布规则

- 提交代码前检查 `git status`，确认 `local.env` 没有出现在待提交文件中。
- 不要把 `local.env`、存档、日志、minidump、`work/runtime` 或备份目录加入发布包。
- 文档中使用 `EU4_GAME_ROOT`、`EU4_USER_DATA` 等变量名，不使用本机用户名、磁盘盘符和个人目录。
- 新增脚本需要本机路径时，应通过 `work/local_config.py` 或 `import-local-env.ps1` 读取配置，不要新增硬编码路径。
- 发布前运行仓库路径扫描，并检查发布打包器的绝对路径泄漏检查；发现个人路径时先清理，再提交或打包。
