# R48：战争赔款与完整条款检查

更新：2026-10-17。本轮把战争赔款（`war_reparations`，下文简称 R）接入统一议和接口，并检查它与金币、省份条款一起出现在同一份和平提议时，原生对象、参数角色、规则检查和序列化副本是否仍然对应。本文记录D的只读查询、E的实际接受与保存、F新进程读回，以及对应的代码和测试证据。

## 目的与判断范围

统一接口需要让 AI 在一份 `peace_context` 中表达战争、方向和多个条款。战争赔款由原生和平提议中的独立条款对象承载。桥接层核对以下关系：

- `war_id` 指向当前战争，`direction` 指明法兰西是索取方还是让步方；
- 金币条款记录金额以及付款方、索赔方；
- 省份条款记录完整的省份编号集合和受益国；
- R 条款记录付款方和索赔方；
- 原生源提议和动作副本包含同一组请求条款，选中数量、字段回读和清理状态相符；
- 每个选中的非零条款都经过原生规则检查。`rule_term_count` 只统计非零金币、选中的省份和 R，不把原生默认的零金币对象计入。

这些条件分别回答“请求选择了什么”“原生对象是否承载了这些选择”和“当前原生规则是否取得可用结果”。规则结果不可用时，事件仍可以是完整的只读观察：R48D 的真实事件使用 `rule_available=false` 和 `NATIVE_PEACE_SELECTED_TERM_RULE_UNAVAILABLE`，同时保留完整的构造、复制、方向和条款数据。

## AI 接口的条款传递方式

AI 调用统一外交接口时，`parameters.peace_context` 承载战争上下文和条款。接口字段名仍是 `peace_context`；其中的 `war_id` 是战争上下文标识，不另造一套 R 专用请求结构。主 `action_id` 可以是 `war_reparations`，也可以是同一份组合中实际作为主动作传递的金币或割省动作。一个包含三类条款的请求形状如下：

```json
{
  "action_id": "war_reparations",
  "actor": "FRA",
  "recipient": "ENG",
  "phase": "initiate",
  "parameters": {
    "peace_context": {
      "war_id": "war_9dfa7bc2c13a42fd_00000001",
      "direction": "offer",
      "terms": [
        {
          "action_id": "demand_ducats",
          "amount": "1.0",
          "payer": "FRA",
          "claimant": "ENG"
        },
        {
          "action_id": "cede_province",
          "province_ids": [4388, 4111, 4112, 4389, 4118],
          "beneficiary": "ENG"
        },
        {
          "action_id": "war_reparations",
          "payer": "FRA",
          "claimant": "ENG"
        }
      ]
    }
  }
}
```

`amount` 使用金币单位，桥接层按 `currency_scale=1000` 传递原始值；例如 `1.0` 对应 `amount_raw=1000`。`province_ids` 是完整集合，`beneficiary` 是每个省份条款的受益国。R 通过自己的 `action_id` 和 payer/claimant 角色传递，不能从主动作或 actor/recipient 的位置猜出角色。

方向决定角色映射：`offer` 表示法兰西向英国提供条款，因此 FRA 是金币和 R 的 payer，ENG 是 claimant，也是省份受益国；`demand` 表示法兰西向英国索取条款，因此 ENG 是 payer，FRA 是 claimant。R48D 的只读组合均使用 `direction="offer"`，事件实际回读为 `payer=FRA`、`claimant=ENG`。

## 完整条款计数与 D 超上限事件

R48D 的组合上限输入包含 1 个非零金币、16 个省份和 R。真实 native 事件因此记录：

- `native_payload.selected_term_count=18`；
- `native_reparations.rule_term_count=18`；
- `rule_scope="selected_nonzero_terms"`；
- `rule_checked=true`、`rule_available=false`；
- `reason_code="NATIVE_PEACE_SELECTED_TERM_RULE_UNAVAILABLE"`；
- 全部 common、wrapper、validity、source/copy 和参数匹配字段为真；`native_evaluation.called=false`。

这里的 18 是“1 个非零金币 + 16 个省份 + 1 个 R”。它与原生容器中的默认条款对象数量不同，也不能用公开 `terms` 数量替代。D 的原始 [超上限组合结果](../../work/runtime/diplomacy-query-20261017-r48-peace-d-selected-term-rules/reparations-query-001/over-cap-combination-result.json) 曾返回 `QUERY_NATIVE_RESULT_INVALID`。回放真实事件后确认，问题出在 Python 验证器复用了旧金币条款验证器：共享的 `native_evaluation` 记录为 `called=false` 时，旧验证器在 `parameters_matched=true` 分支要求评价调用已发生；而原生在选中条款规则不可用时本来就不会调用评价函数。

验证器现已把这种情况作为内部的不可用评价视图传给旧金币验证器，同时继续严格检查 event、日期、会话、战争、方向、payer/claimant、金额、省份、源副本、`rule_term_count`、`rule_scope` 和 reason code。缺失字段、错误计数、错误 scope 或未知 reason 仍然拒绝。真实 R48D 事件回放测试已通过；它修正了结果映射，不把原生 `rule_available=false` 改写成接受或拒绝结论。

E 查询了三个超出费用上限的组合：16省组合、五省加巴黎和上普瓦图的七省组合、五省加巴黎的六省组合。三者都返回原生中文原因“不能提供超过100%战争分数价值的条件”。另一个包含上普瓦图和内穆尔的七省组合返回“不能选择这个省份，因为英格兰无法将其核心化”。这些查询取得了费用限制和省份资格两类原生判断。对应证据见 [E 超上限结果](../../work/runtime/diplomacy-query-20261017-r48-peace-e-native-rule-transaction/reparations-query-001/over-cap-combination-result.json)、[E 七省结果](../../work/runtime/diplomacy-query-20261017-r48-peace-e-native-rule-transaction/reparations-query-001/near-cap-combination-result.json)、[E 巴黎组合结果](../../work/runtime/diplomacy-query-20261017-r48-peace-e-native-rule-transaction/reparations-query-001/near-cap-paris-result.json) 和 [E 上普瓦图与内穆尔结果](../../work/runtime/diplomacy-query-20261017-r48-peace-e-native-rule-transaction/reparations-query-001/near-cap-poitou-nemours-result.json)。

## 原生费用重复计入与 E 修正

R 条款的费用检查暴露了一个真实的原生调用问题：如果把已经包含 R 的完整 `CPeaceOffer` 再连同当前 R 候选直接送入条款规则函数，完整提议已经贡献过一次 R，候选调用还会再贡献一次，费用就会重复计入。普通选中条款可以使用原生的 skip-cost 入口，但 R 需要保留完整提议的费用检查，不能简单跳过。

E 版本在 `peace-reparations-selection.inc` 中复用了原生 `99d220` 的选择变更事务：先记录金币数量和临时选择变更，临时移除当前战争赔款条款并重算提议费用，再调用 `97a030`。这次原生检查将剩余提议费用与战争赔款的增量相加，得到完整提议费用；随后调用原生 `993520` 恢复选择位、临时向量、金币数量和派生状态。恢复后的序列化提议必须与检查前相等。其他选中条款使用原生 skip-cost=1 检查资格和组合限制，完整提议的费用上限由上述战争赔款检查统一判定。
